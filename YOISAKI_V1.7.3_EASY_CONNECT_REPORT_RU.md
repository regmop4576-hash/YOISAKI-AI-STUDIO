Основа: архив `YOISAKI_AI_STUDIO_V1.7.3_ONE_CLICK_CONNECT.zip` (ранняя сборка 1.7.3 поверх 1.7.2, её отчёт — `YOISAKI_V1.7.3_REPORT_RU.md`). Версия студии 1.7.3, пакет CloudCompute 1.7.3, протокол движка **1.7.0 без изменений**: каталог `engine/` и Colab-блокнот побайтно совпадают с основой (проверяют `test_engine_files_match_current_package_manifest` и `test_notebook_package_is_byte_identical_to_engine`). Генерация, качество изображений, очередь, память GPU, Text2Img / Img2Img / Multi-LoRA / ControlNet / Regional Control, история, пресеты и галерея не изменялись.

Обозначения способа проверки: **[локально]** — запуск в среде разработки (Linux x86_64, без GPU); **[моки]** — внешние сервисы заменены тестовыми двойниками; **[реально]** — реальный внешний сервис. **Проверок [реально] с CloudCompute API, Google OAuth, GPU и Android в этой версии нет.**

## 2. Изменения

### 2.1. CloudCompute API (P0)
- `server/cloudcompute-api.mjs` — адаптер `https://app.cloudcompute.ru/api/v1`. Эндпоинты не зашиты: они берутся из строго проверяемого описания (`parseContract`): только `GET`/`POST`, относительные пути, `{id}` по правилам, обязательные `verified_against`, `fields.id/status`, `status_map`. Операции `delete` в описании быть не может. Ответы нормализуются, все строки провайдера очищаются от ключей и токенов (`scrub`).
- `server/https-json.mjs` — HTTPS-клиент для фиксированных хостов: DNS разрешается один раз, все адреса обязаны быть публичными (защита от DNS rebinding/SSRF), соединение привязывается к адресу, TLS проверяется по имени хоста, перенаправления не выполняются, размер ответа ограничен.
- `server/secrets.mjs` — разделы `cloudcompute` (ключ, время сохранения/проверки, выбранный инстанс) и `drive` в `secrets.json` (0600).
- `server/app.mjs` — маршруты `/api/cloudcompute*`, `/api/gpu/connect-gpu` (сценарий: инстанс → подтверждённый запуск → ожидание RUNNING до 10 минут → прежнее подключение к движку). Остановка выбранного инстанса завершает сеанс движка (история остаётся «не подтверждена», а не «завершена»). Ключ API никогда не передаётся движку (проверено тестом по всем вызовам upstream).
- `server/connect-flow.mjs` — ошибки `CC_*` не окрашивают туннель/движок в «ошибку»; отдельный компонент «GPU-инстанс».
- UI: `src/components/CloudComputeApi.tsx`, `src/app/engine/page.tsx` (панель, ПОДКЛЮЧИТЬ GPU, шаг «GPU-инстанс», подтверждение оплаты, английские сообщения).

### 2.2. Google Drive Easy Connect (P1)
- `server/google-oauth.mjs` — PKCE/loopback сохранены; добавлены общий клиент дистрибутива (`YOISAKI_GOOGLE_CLIENT_ID/SECRET` или `config/google-oauth-client.json`), обновление access token, отзыв (`/revoke`, токен в теле запроса), `prompt=consent select_account`.
- `server/google-drive.mjs` — Drive API v3 (только чтение, фиксированный хост): аккаунт (`about`), папки (`Мой диск` / `Доступные мне`), путь папки, предпросмотр моделей (те же папки, глубина и форматы, что у синхронизации на GPU; ограничения на число запросов и файлов).
- `server/drive-account.mjs` — привязка Drive установки: refresh token только в `secrets.json`, access token только в памяти, `invalid_grant` → состояние «нужен повторный вход», новый вход другим аккаунтом сбрасывает папку.
- **Изменение решения ранней 1.7.3:** там refresh token не хранился на телефоне (сразу уходил на GPU), поэтому Drive нельзя было настроить без GPU. Требование 5.6 это запрещает, поэтому токен теперь хранится локальным сервером (0600, не браузер). Тест ранней сборки обновлён: токен присутствует только в `secrets.json`, ни в одном другом файле и ответе API.
- Передача на GPU (`provisionDrive`): при подключении CloudCompute — `/sync/drive/connect` с токеном, клиентом и папкой (`folder_id` только для серверов, сообщающих `folder_select`), затем (опционально) `/sync/start`. Ошибки показываются на странице «Модели» и не влияют на подключение GPU.
- GPU: `cloudcompute/drive_sync.py`, `sync_api.py` — `folder_id`/`folder_label` → `root_folder_id` в `rclone.conf` + `runtime/sync/source.json` (0600); поле `source_kind`, `folder_select`. Старые сайты (без папки) работают как раньше.
- UI: `src/components/DriveSync.tsx` переписан: аккаунт, папка, обозреватель папок, предпросмотр, три состояния, настройки передачи/автозагрузки, прежняя синхронизация на GPU; ручной способ Termux — в «Дополнительно».

### 2.3. Быстрая установка (P2)
- `start-cloudcompute.sh` — `YOISAKI_PREBUILT_IMAGE`: скачивание готового образа, только если метка `org.yoisaki.source` равна хэшу файлов движка; иначе прежняя локальная сборка. `.github/workflows/engine-image.yml` — публикация образа в GHCR.
- Без изменений, но проверено чтением кода: повторный запуск переиспользует venv (маркер по хэшу закреплённых зависимостей и версии Python), модели не скачиваются повторно, время запуска пишется в `diagnostics/startup-timings.jsonl`.

### 2.4. Модели (P3)
- **Amber_Nova / Vesper_Nova.** Исправления ранней 1.7.3 (D1–D6: фильтр `compatible:false`, устаревший кэш, «склеивание» принудительного обновления, ошибка обновления, отбрасывание каталога из-за одной записи, тяжёлые метаданные) перепроверены тестами `v173-one-click.test.mjs` — проходят. Новых дефектов не найдено. Эвристика совместимости движка не менялась (менять `engine/` вслепую было бы ошибкой).
- **ControlNet в синхронизации — не добавлен намеренно.** Движок берёт модели ControlNet из фиксированных репозиториев (`engine/inference/controlnet.py`, `MODELS[mode]`), а не из `models/controlnet`. Синхронизация таких файлов создала бы видимость поддержки. Предпросмотр папки сообщает об этом пользователю.
- Страница «Модели» переведена на английский полностью.

## 3. Безопасность (обзор)
- Локальный API: проверка `Host` (защита от DNS rebinding), `Origin`, `Sec-Fetch-Site`, заголовок `X-Yoisaki-Local`, cookie сессии `HttpOnly; SameSite=Strict`. Новые маршруты под теми же правилами; тест подтверждает, что запросы с чужим Origin/Host/без заголовка/кросс-сайт получают 403 и **не доходят до CloudCompute**.
- Платные действия требуют `confirm:true` на сервере и диалога в UI.
- Секреты не попадают: в ответы API, `state.json`, диагностику, журнал событий, браузерное хранилище, URL (тесты Node и браузерный тест). Сообщения провайдеров очищаются.
- Внешние хосты фиксированы (`app.cloudcompute.ru`, `oauth2.googleapis.com`, `www.googleapis.com`), частные IP запрещены, TLS проверяется.
- Аутентификация движка (Bearer) не изменена и не ослаблена; ключ CloudCompute на GPU не передаётся.
- Известный компромисс: копия refresh token Google находится и на GPU-сервере пользователя (нужна rclone для загрузки). Отзыв в «Отключить Google Drive» аннулирует обе копии.

## 5. Известные ограничения
1. Описание методов CloudCompute API не сверено с документацией → управление инстансами выключено до заполнения `cloudcompute-api.json` (раздел 1).
2. Ни один реальный внешний сервис не проверялся. Реальные ответы CloudCompute API могут потребовать поправок в описании (не в коде).
3. Google: `drive.readonly` — restricted scope; общий клиент для публичного приложения требует проверки Google и CASA; режим Testing — повторный вход каждые 7 дней. Loopback-перенаправление в Chrome на Android работает, пока запущен Termux; на реальном устройстве не проверялось.
4. Refresh token хранится и на телефоне (0600), и на GPU-сервере пользователя.
5. Готовый Docker-образ и workflow не проверялись; поддержка Docker на инстансах CloudCompute неизвестна.
6. Первая установка движка на инстанс — вручную, один раз (SSH/Jupyter). Цель «запуск до 10 минут» не измерялась.
7. Пользовательские ControlNet-модели не синхронизируются (движок их не использует).
8. Генератор по-прежнему локализуется через `LocaleBridge` (не менялся).
9. Название верхней папки архива `YOISAKI_AI_STUDIO_V1.4.0_LOCAL_EDITION` сохранено: на него рассчитан `update.sh` установленных версий.
