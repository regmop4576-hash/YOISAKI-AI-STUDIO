## Итог

- **Без GPU** (сценарий A): Модели → GOOGLE DRIVE → **ПРОВЕРИТЬ GOOGLE DRIVE**. Показывается реальный список выбранной папки с вложенными папками: тип по правилам движка, размер, дата, контрольная сумма, ревизия, права. Модели можно выбрать заранее. Нужен только сохранённый вход Google: ни GPU, ни SSH, ни Termux-команд.
- **С GPU** (сценарий B): после «GPU готов» скачиваются **только выбранные** модели. Монитор показывает реальные байты, процент, скорость, ETA и файлы. Состояние переживает перезагрузку страницы и перезапуск Termux, загрузка при этом не начинается заново. После завершения каталог GPU обновляется, и для каждого нового файла видно, доступен ли он в генераторе.

**Не проверено вживую:** настоящий Google Drive (в среде разработки нет OAuth-аккаунта пользователя) и настоящий GPU CloudCompute. Передача файлов при этом проверена **настоящим** стеком GPU-синхронизации — `drive_sync.py` + `sync_api.py` + `rclone` — по HTTP, см. «Проверки».

## Что сделано

| Требование | Реализация |
|---|---|
| 2. Браузер Google Drive без GPU | `server/drive-library.mjs`, вкладка **GOOGLE DRIVE**. Используется токен OAuth из `secrets.json`, обновляется автоматически, повторный вход не нужен. Рекурсивный обход выбранной папки: пагинация по 1000, до 500 папок и 3000 файлов моделей, ярлыки на папки и файлы, Google Docs пропускаются (как `--drive-skip-gdocs`). Режим «По папкам»: хлебные крошки, родительские папки (выше выбранной — только просмотр, выбор не меняется), поиск в папке, «Ещё файлы». Поиск и фильтры по всему списку. |
| 2.3 Форматы и типы | Тип по папке, как в `engine/worker/models.py`: `checkpoints/`, `loras/`, `vae/`, `controlnet/`; вне их — Unknown. Архитектура и совместимость — только из настоящего заголовка safetensors, правила `inspect()` движка перенесены построчно. Заголовок читается Range-запросом: 64 КБ, при большом заголовке — ещё один точный запрос; веса не скачиваются, а если сервер игнорирует Range, чтение обрывается на запрошенном объёме. Проверка «размер = 8 + заголовок + данные» из `fetch_models.validate()` находит недокачанные на Drive файлы. `.ckpt/.pt/.pth/.bin` видны с причиной «pickle не загружается». ControlNet виден с пояснением: генератор 1.7.0 берёт его из Hugging Face. Сверка с настоящим Python-кодом `drive_sync.classify()` и `inspect()` — отдельный тест. |
| 2.5 CHECK GOOGLE DRIVE | Шаги: проверка OAuth (`/about`), проверка папки (существует, не в корзине, это папка), список, сохранение времени. Состояния: VERIFIED (только в ответе самой проверки), CACHED, NONE, NOT_CONNECTED, FOLDER_NOT_SELECTED, AUTH_EXPIRED, PERMISSION_DENIED (по `error.errors[].reason` Google), FOLDER_NOT_FOUND, OFFLINE, RATE_LIMITED. Сохранённый список никогда не показывается как свежий. При ошибке он остаётся с пометкой «не подтверждён». Файлы без права скачивания (`canDownload=false`) показаны с явной причиной. |
| 3. Раздельные источники | Вкладки **GOOGLE DRIVE / МОДЕЛИ GPU / СИНХРОНИЗАЦИЯ**. Фильтры Checkpoints/LoRA/VAE/ControlNet сохранены. «Модели GPU» без GPU помечены «кеш, недоступна». «Синхронизация» группирует: только на Drive, установлены на GPU, требуют обновления, загружаются, не прошли проверку, не синхронизируются, только на GPU. «Установлена на GPU» показывается только по данным GPU. |
| 4. Выбор до аренды GPU | Мультивыбор, «Выбрать все», «Снять выбор». Сохраняется в `drive-library.json` (0600) и привязан к папке. Показываются объём загрузки, место на диске GPU (с резервом 2 ГБ синхронизации) и предупреждение о нехватке: по плановому диску (минус образ ~13 ГБ) или по свободному месту на GPU. Нельзя выбрать то, что GPU отклонит. **Изменение поведения 1.7.5:** автоматическая загрузка после «GPU готов» берёт только выбранные файлы, а без выбора ничего не скачивает. «Все недостающие» — только кнопкой с подтверждением. |
| 5. Монитор в реальном времени | `server/sync-monitor.mjs`. Единственный источник — ответ `/sync/status` GPU: байты, `speed_bps` (окно 5 с потока rclone), состояния файлов. Структурированные события выводятся сравнением ответов: JOB_STARTED, STAGE, FILE_STARTED (с `resumed_from`), FILE_INSTALLED, FILE_FAILED, JOB_FINISHED, GPU_UNREACHABLE, GPU_RECONNECTED, INVENTORY_REFRESHED. ETA = (всего − готово) / скорость; без скорости — «Вычисляется…» или «Недоступно». Резервная скорость считается только по двум реальным замерам `bytes_done` не ближе 3 с, с пометкой «по наблюдению телефона». Транспорт — опрос существующего API: 2 с при активном задании, телефон дополнительно следит сам каждые 3 с. SSE/WebSocket не добавлены: через туннель Cloudflare опрос проще и надёжнее, второй сервис синхронизации не создавался. |
| 5.3 Восстановление | `sync-monitor.json` (0600) хранит ID задания, последний ответ и журнал; ID задания также лежит в `localStorage`. После перезагрузки или перезапуска Termux — сначала «последнее известное» состояние, затем живое. Повторного `/sync/start` нет (проверено тестами, в том числе на настоящем rclone). |
| 5.4 Состояния | IDLE, CHECKING_DRIVE, COMPARING_FILES, WAITING_FOR_GPU, DOWNLOADING, VERIFYING, COMPLETED, CANCELLED, ERROR — подписи на русском и английском. Тип ошибки различается: синхронизация, доступ Google Drive, связь с GPU. Для каждого кода `drive_sync.py` есть совет, что делать. |
| 6. Надёжность | Механизмы GPU 1.7.5 не тронуты: `.part`, докачка `--offset`, контрольная сумма + safetensors, атомарный `rename`, пропуск установленных, CHANGED, отмена. | 7. Обнаружение моделей | После задания — принудительное обновление каталога, затем отчёт по каждому файлу: AVAILABLE / AVAILABLE_UNVERIFIED / INCOMPATIBLE (с причиной движка) / NOT_FOUND / NOT_INSTALLED. Без перезапуска движка. LoRA с неподтверждённой совместимостью видны в генераторе (как в 1.7.3). Amber_Nova и Vesper_Nova проверены сквозным браузерным тестом до списка LoRA генератора. |

Индикаторы: API, инстанс, движок, CUDA, GPU, VRAM, диск моделей, Google Drive (телефон и GPU), синхронизация. **ГОТОВ К ГЕНЕРАЦИИ** — только при успешном health движка и совместимом checkpoint. |

## Известные ограничения

1. Живые Google Drive API и GPU CloudCompute не проверялись. Обязательная приёмка — первый реальный запуск. Если Google отдаст `alt=media` через перенаправление, разрешены только хосты `*.googleusercontent.com`, токен туда не передаётся. Если чтение заголовка не сработает, сообщение будет явным, а тип останется «не проверена» — без выдуманных значений.
2. Синхронизация на GPU — без изменений 1.7.5:
   - только `checkpoints/`, `loras/`, `vae/`, `.safetensors`;
   - глубина — две подпапки;
   - до 2000 файлов;
   - ControlNet-файлы не синхронизируются (генератор берёт ControlNet из Hugging Face).

   Расширение потребует нового образа движка 1.7.6. Сознательно не делалось: опубликованный образ 1.7.5 остаётся рабочим.
3. Скорость от GPU — скользящее окно 5 с. При коротких файлах ETA может быть «Вычисляется…» почти до конца файла.
4. На телефоне монитор работает, пока жив Termux. Если Android остановил Termux, загрузка на GPU продолжается, а журнал событий за это время восстанавливается по следующему ответу GPU: промежуточные события по файлам могут быть сведены в одно.
5. Поиск «По папкам» — по имени в текущей папке (возможности Drive API). Поиск по всей библиотеке — во вкладке «Все модели».
6. Совместимость VAE и LoRA без метаданных базовой модели — «не подтверждена». Так решает и движок.

## Обновление с 1.7.5 на Android

```bash
cd ~/YOISAKI_AI_STUDIO_V1.4.0_LOCAL_EDITION
bash update.sh ~/storage/downloads/YOISAKI_AI_STUDIO_V1.7.6_MODEL_LIBRARY.zip
```

Скрипт проверяет архив, делает резервные копии кода и данных и запускает сайт. Вход Google, выбранная папка, ключ CloudCompute, сохранённый GPU-сервер, галерея и история сохраняются. Повторная авторизация не нужна. Новый образ движка не нужен: GPU-серверы на `engine:1.7.5` работают с 1.7.6 без изменений.

Откройте `http://127.0.0.1:3000/engine` и проверьте строку «AMBER CORE · v1.7.6 ZERO-TERMINAL CLOUDCOMPUTE EDITION». Затем: **Модели → GOOGLE DRIVE → ПРОВЕРИТЬ GOOGLE DRIVE**.

## Откат

`update.sh` оставляет `~/YOISAKI_AI_STUDIO_V1.4.0_LOCAL_EDITION.backup-<дата>` и `~/.local/share/yoisaki-ai-studio.backup-<дата>`.

```bash
cd ~ && bash YOISAKI_AI_STUDIO_V1.4.0_LOCAL_EDITION/stop.sh
mv YOISAKI_AI_STUDIO_V1.4.0_LOCAL_EDITION YOISAKI_AI_STUDIO_V1.7.6.disabled
mv YOISAKI_AI_STUDIO_V1.4.0_LOCAL_EDITION.backup-<дата> YOISAKI_AI_STUDIO_V1.4.0_LOCAL_EDITION
cd YOISAKI_AI_STUDIO_V1.4.0_LOCAL_EDITION && ./start.sh
```

Данные совместимы в обе стороны. Новые файлы `drive-library.json` и `sync-monitor.json` версия 1.7.5 не читает, `state.json` и `secrets.json` 1.7.6 не меняет. Восстанавливать каталог данных нужно только при его повреждении. Откат не останавливает и не удаляет инстансы CloudCompute.
