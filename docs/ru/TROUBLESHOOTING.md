# Если что-то не работает

Первый шаг почти всегда один — диагностика:

```bash
cd ~/YOISAKI_AI_STUDIO_V1.4.0_LOCAL_EDITION && ./diagnostics.sh
```

Она покажет версию сайта, Node.js, работает ли сервер, **из какой папки** он запущен, соответствует ли сборка
исходникам и безопасный хвост журнала (токены скрыты). Её вывод можно приложить к вопросу — но всё равно
проверьте, что в нём нет ссылок с `#token=`.

## Установка и запуск в Termux

Ошибки команды установки (`install-termux.sh`) — в [INSTALL_TERMUX.md](INSTALL_TERMUX.md#7-если-команда-не-сработала).
Вместо `cd …LOCAL_EDITION && ./start.sh` можно использовать `yoisaki start`, `yoisaki stop`, `yoisaki status`.

| Сообщение / симптом | Причина и решение |
|---|---|
| `Файлы приложения отсутствуют или повреждены. Распакуйте полный исходный ZIP заново.` и строки `SHA-256 не совпадает` / `файл отсутствует` | Архив скачан не полностью, распакован поверх другой версии или файлы изменены. **Не отключайте проверку.** Удалите папку, скачайте `YOISAKI_AI_STUDIO_V1.9.2_PIXEL_FANTASY.zip` заново (сверьте SHA-256 с `SHA256SUMS.txt`) и распакуйте в пустую `~`. Для существующей установки используйте `update.sh`. |
| `Переместите папку приложения в домашнюю папку Termux (~).` | Папка лежит в `/sdcard` или `~/storage/...`. Распакуйте архив командой `cd ~ && unzip -q …`. |
| `Нужен Node.js 22–26; рекомендуется 24 LTS.` | `pkg upgrade nodejs-lts`, затем `node -v`. |
| `Установите Node.js 22 или 24 LTS.` | Вы не в Termux и Node.js не установлен. В Termux: `pkg install nodejs-lts`. |
| `unzip: command not found` | `pkg install -y unzip`. |
| `No such file or directory` для `~/storage/downloads/...` | Выполните `termux-setup-storage`, разрешите доступ, проверьте имя файла: `ls ~/storage/downloads`. |
| `Production build does not match installed sources. Run bash install.sh.` | Файлы изменены после установки. `bash install.sh` (при несовпадении он пересоберёт сайт — нужен интернет). Если не помогает — переустановите из ZIP. |
| `Порт 3000 занят.` | Остановите другую копию (`./stop.sh`) или `PORT=3001 ./start.sh`. |
| `Сервер уже работает из …` | Сервер уже запущен — откройте http://127.0.0.1:3000. Если указана **другая папка** (старая копия), выполните там `./stop.sh`, затем `./start.sh` в нужной. |
| После обновления сайт выглядит по-старому | Работает старая копия или браузер показывает кэш. `./diagnostics.sh` → «Папка запущенного сервера» и «Версия запущенного сервера». Затем потяните страницу вниз для обновления. |
| `Сервер не запустился. Выполните ./diagnostics.sh` | Смотрите хвост журнала в выводе диагностики. |
| Сайт перестал открываться, когда Termux был свёрнут | Android остановил Termux. Снимите ограничения батареи для Termux или `termux-wake-lock`, затем `./start.sh`. |
| `YOISAKI_DATA_DIR внутри приложения…` (при `update.sh`) | Папка данных не должна лежать внутри папки приложения. Перенесите данные и задайте новый `YOISAKI_DATA_DIR`. |
| `Небезопасный путь в архиве` / `Символические ссылки … запрещены` | Архив не является официальным релизом. Скачайте ZIP из Releases. |
| `В архиве не найдена локальная редакция приложения.` | Передан не тот ZIP (например, «Source code»). Нужен `YOISAKI_AI_STUDIO_V…_PIXEL_FANTASY.zip`. |
| `Запуск не удался. Код предыдущей версии восстановлен…` | Новая версия не запустилась, `update.sh` вернул прежнюю. Данные целы. Запустите `bash start.sh` и пришлите вывод `./diagnostics.sh`. |

## Google Colab и подключение GPU

| Сообщение на сайте | Что делать |
|---|---|
| «Неверный токен в ссылке» / «Сервер отклонил токен…» | Скопируйте **новую** ссылку из панели Colab **целиком** вместе с `#token=…`. После перезапуска движка старый токен недействителен. |
| «GPU-сервер не ответил вовремя», «Соединение с GPU-сервером прервалось» | Проверьте, что вкладка Colab открыта и сессия жива. Подождите и нажмите «Подключиться» ещё раз. |
| «Туннель работает, но движок за ним не отвечает…» | Движок ещё запускается или остановлен. Посмотрите статусы в панели Colab. |
| «По адресу отвечает не движок YOISAKI…» | Туннель показал страницу ошибки — движок перезапускается. Подождите. |
| «Движок отвечает, но CUDA/GPU недоступны» | В Colab не выбран GPU. «Среда выполнения» → «Сменить среду выполнения» → T4 GPU, затем запустите блокнот заново. |
| «Версия движка несовместима: нужен YOISAKI ENGINE 1.7.0, 1.7.6, 1.8.0 или 1.8.1 (API 1.7.0)…» | Открыт старый блокнот. Используйте `YOISAKI_ENGINE_V1.9.2_COLAB.ipynb`. |
| «Адрес указывает на частную сеть», «Неверный адрес сервера», «Адрес перенаправляет запрос…» | Вставлена не ссылка из панели Colab. Нужна ссылка `https://….trycloudflare.com/#token=…`. |
| «Подключённый движок не поддерживает Face Fix» / нет автоматического поиска лиц | Нужен движок 1.8.1 — запустите блокнот v1.9.2. |
| В Colab: «Файлы движка повреждены…» | Блокнот изменён или скачан не полностью. Откройте его заново из репозитория/релиза. |
| В Colab: «⚠ Подготовка не завершена…» | Проверьте интернет и T4, повторите ячейку. Не помогает — «Отключиться от среды выполнения и удалить её» и запустите блокнот заново. |
| Colab не даёт GPU / сессия оборвалась | Ограничение бесплатного Colab. Попробуйте позже; после перезапуска вставьте новую ссылку. |

## Модели и генерация

| Симптом | Что делать |
|---|---|
| Список моделей пуст | Drive подключён? Папки точно `MyDrive/YOISAKI_AI_STUDIO/models/checkpoints` и т.д.? Расширение `.safetensors`? Нажмите «🔄 ОБНОВИТЬ МОДЕЛИ» в Colab и «Обновить модели» на сайте. |
| «Модель несовместима. Выберите SDXL / Illustrious XL в формате safetensors.» | Это не SDXL-модель (например, SD 1.5). См. [MODELS_AND_LORA.md](MODELS_AND_LORA.md). |
| «Модель не найдена. Нажмите «Обновить модели».» | Файл переименован или удалён с Drive. Обновите список. |
| Не хватает памяти / сессия Colab падает | Уменьшите разрешение, количество изображений до 1, число LoRA; выключите ControlNet. |
| LoRA почти не влияет | Добавьте её триггер-слова в промпт, проверьте вес и что LoRA обучена под SDXL/Illustrious. |

## Данные

- Галерея хранится в браузере телефона (IndexedDB). Очистка данных сайта в браузере удалит галерею.
- Настройки и пресеты — в `~/.local/share/yoisaki-ai-studio`. При повреждении `state.json` сервер пытается
  восстановить `state.json.bak` и сохраняет повреждённый файл отдельно — не удаляйте их вручную.
- `update.sh` делает резервную копию данных перед каждым обновлением.

Подробные старые заметки: `docs/TROUBLESHOOTING_RU.md`, `TERMUX_INSTALL_FIX_RU.md`,
`YOISAKI_STARTUP_ROOT_CAUSE_REPORT.md`.
