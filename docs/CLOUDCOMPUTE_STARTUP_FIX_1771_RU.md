# Запуск CloudCompute после исправления 1.7.7.1

Используйте обычное обновление YOISAKI из ZIP, сохраняя существующую папку данных. Историческое имя каталога внутри архива оставлено для совместимости `update.sh`.

## Новый инстанс

После публикации образа 1.7.7.1: найдите GPU → проверьте предложение → подтвердите аренду. Оставьте профиль `worker`. Сайт передаст токен/onstart и будет следить за реальным состоянием. При отсутствии сигналов выполнится ограниченная попытка запуска через официальный веб-терминал. Кнопка «Инициализировать движок» теперь действительно запускает provisioning. Готовность хоста не равна готовности генерации.

**Образ 1.7.7.1 опубликован 28.10.2026 (digest `sha256:a148c0e8f5df410454c33dc4bef902fbfad412ddfc9b357e487f02a9ce4964dc`, анонимный manifest: HTTP 200), проверка образа на сайте проходит.** Не отключайте проверку образа ради новой платной аренды. Реальный запуск на GPU ещё не подтверждён.

## Уже существующий инстанс

На GPU-странице выберите нужный инстанс или в расширенных настройках укажите его ID и нажмите «Подключить и запустить». Сайт запросит терминал и выполнит существующий `/opt/yoisaki/cloudcompute/autostart-image.sh --provision`. Работающий сервер не считается READY до проверки health. Файлы/модели не удаляются.

При ошибке автоматизации воспользуйтесь «Резервная команда»: скопируйте её один раз в веб-терминал **этого** инстанса в панели CloudCompute. Не публикуйте команду — она содержит отдельный токен движка. Код завершения и ошибка видны явно. Вложенный Docker и ручная установка Python не используются.

Контейнер 1.7.7 автоматически не становится 1.7.7.1. Для полного набора исправлений супервизора нужен новый образ. Нельзя гарантировать запуск, если провайдер не исполнил onstart и не предоставил рабочий терминал.

## Если готовности нет

Скачайте «Диагностика (JSON)». Проверьте profile, provisioning_requested, provisioning_completed, supervisor_confirmed, required_directories, health и startup error. unavailable означает отсутствие наблюдения. Raw status `1` сохраняется, но не интерпретируется как success без документированного enum. В терминале ничего удалять либо менять `/.launch` не требуется.

Google Colab и прежний способ подключения сохранены. Реальная проверка исправления на CloudCompute/GPU ещё не выполнена.
