# YOISAKI AI STUDIO v1.5.4 — история и версии

Дата: 25 октября 2026. Основа: ранее выданный 1.5.3 REGIONAL_COMPAT_HOTFIX из текущей рабочей среды. Нового исходного архива в последнем запросе не приложено; проект не пересоздавался.

## Где хранилась история

Источник истины — Node Store, `state.json` в `YOISAKI_DATA_DIR`, по умолчанию `~/.local/share/yoisaki-ai-studio`. Массив `history` сохраняется через последовательную очередь Store.change, временный файл, fsync и atomic rename. Предыдущая версия state сохраняется в `.bak` для восстановления повреждений.

Generate держит временную React-копию ответа `GET /api/history`, обновляемую раз в 2 секунды. История не хранится в localStorage или IndexedDB. Zustand хранит настройки и пресеты через API `/api/settings`, а не саму историю. Галерея — отдельный массив `gallery` в state.json и отдельные файлы в `images/`; её элементы содержат собственные prompt, parameters, favorite, seed и job_id.

Старые карточки накапливались потому, что сервер добавлял history при каждой отправке и не имел удаления или retention. Интерфейс выводил все записи подряд. Никакая браузерная очистка не решала бы проблему постоянного источника истины.

## Удаление и защита

Добавлен `DELETE /api/history/{id}`. Это удаление локальной записи, не отмена задания и не удаление изображения. Проверка допустимости и фильтрация выполняются внутри сериализованной Store.change. UI меняется после успешного сохранения; при ошибке диска запись остаётся и показывается ошибка. Устаревший ответ polling не возвращает удалённую карточку: применяется счётчик ревизий UI, а серверные поздние обновления меняют только существующие записи без upsert.

Добавлен `POST /api/history/cleanup` с scope и явным списком подтверждённых пользователем IDs. На момент записи повторно проверяются статус и участие в опросе GPU. Новые задания, завершившиеся после подтверждения, не удаляются этим запросом.

Терминальные состояния взяты из существующего локального сервера: COMPLETED, FAILED, CANCELLED, INTERRUPTED. Политика вынесена в server/history.mjs. RUNNING, QUEUED и неизвестные статусы защищены; прежняя отмена сохранена.

**CONNECTION_LOST — особый случай:** в существующей машине состояний это НЕ terminal. Так помечается даже отправленный запрос, для которого ещё не получено подтверждение. Его нельзя безопасно считать старым завершённым заданием. Кнопка «Проверить и удалить» сначала восстанавливает статус через прежнюю сессию GPU. Если remote завершился успешно, изображение сначала сохраняется в Gallery, затем удаляется история. Если remote FAILED/CANCELLED либо подтверждено отсутствие задачи (INTERRUPTED), запись удаляется. Если GPU недоступен, сессия другая или задача ещё выполняется — запись остаётся с объяснением. Массовая и автоматическая очистка CONNECTION_LOST не удаляют. Это намеренная защита возможной активной генерации, а не визуальное скрытие записи.

Удаление не обращается к deleteImage, не меняет gallery, favorites, settings, tags, models или preferences и не удаляет файлы. После reload/restart/reconnect удалённые записи не восстанавливаются: reconnect перебирает только оставшуюся локальную историю. Восстановление повреждённого state.json из старого `.bak` остаётся прежним аварийным механизмом; это не штатный перезапуск и может восстановить предыдущий снимок данных.

## Retention

Сохраняются последние 50 terminal records по updated, с fallback на created; при равных timestamps сохраняется исходный порядок. Все nonterminal сохраняются сверх этого числа. Лимит применяется при загрузке старого хранилища и в общей сериализованной операции записи. Когда terminal ≤ 50, сортировка не производится. Очистки по React render и фонового цикла повторных записей нет. Ошибка сохранения не заменяет состояние в памяти.

Лимит относится к локальной истории сайта. Независимые служебные записи внутри живой Colab-сессии не удаляются и Python engine не изменялся.

## Интерфейс

Активные и неподтверждённые задания остаются снаружи свёрнутого блока. Завершённые находятся в «История генераций (N)», свёрнутой по умолчанию; каждую карточку можно раскрыть. Кнопка корзины вынесена отдельно от summary и имеет минимум 44×44 px. Меню «Очистить» содержит успешные, неуспешные и все завершённые; confirm показывает число выбранных записей и сохранность Gallery.

Generate controls, цвета, шрифты, навигация, Editor, Models, Gallery, Trigger Manager и Regional editor не переделывались. В Shell/Settings/GPU изменены только сведения о версиях. В Generate удаление выбранного элемента сбрасывает локальную ссылку на эту карточку; само изображение остаётся доступно в Gallery.

## Версии

Сайт: 1.5.4. Python: 1.5.3. Это совместимые, но разные компоненты.

Обновлены package.json/package-lock.json, `/api/session`, `/api/diagnostics`, startup/diagnostics script banners, Shell, Settings и подпись сайта на GPU-странице. API status содержит website_version, compatible_engine_family='1.5.x', compatibility. Для известных YOISAKI_ENGINE 1.5.x (включая 1.5.2.1) — COMPATIBLE; без подключения — NOT_CONNECTED; неизвестный контракт — UNVERIFIED.

Региональная проверка из предыдущего hotfix сохранена: явный capabilities.regional_control имеет приоритет, при отсутствии — известное семейство 1.5.x; explicit false не обходится версией. Неизвестный движок не объявляется полностью совместимым только по одному региональному флагу. ACK при reconnect переведён с точного 1.5.1 на семейство 1.5.x — это устранение оставшейся устаревшей проверки совместимости и сохранение подтверждения уже записанных результатов.

Изменений Python нет. Встроен прежний notebook 1.5.3 без переименования версии. Старые документы с историческими версиями оставлены как архивная справка; инструкция текущего выпуска находится в docs/TERMUX_UPDATE_RU.md. Имя внутренней папки v1.4.0 оставлено ради существующего update.sh — оно не означает версию приложения.

## Что проверено и что осталось

23 серверных теста, TypeScript, production build и 3 браузерных сценария прошли. Есть тесты ошибок диска, race completion/cleanup, очистки после restart, сохранения пользовательских данных и изменения статуса до commit. Вся Python-часть и notebook побайтово совпадают с 1.5.3.

Нет физического Android и NVIDIA T4. Браузерные генерации используют synthetic upstream только в тестах. Настоящие CUDA/Colab-генерации не выдаются за проверенные в этом выпуске.
