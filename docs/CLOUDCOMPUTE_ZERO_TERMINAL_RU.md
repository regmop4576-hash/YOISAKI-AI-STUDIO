# YOISAKI AI STUDIO 1.7.5 — CloudCompute без терминала

Для уже настроенной установки на Android (сайт работает, ключ CloudCompute сохранён, Google подключён, папка моделей выбрана). SSH, Python, pip и команды Termux при обычной работе не нужны.

## Обычный запуск GPU

Откройте **GPU → CloudCompute**. Под полем API-ключа находится блок **CLOUDCOMPUTE** с пятью шагами.

1. **Выбрать GPU.** Приложение запрашивает у CloudCompute список предложений (`GET /offers`) и показывает подходящие карточки: GPU, VRAM, цену в час, максимальный диск, CUDA, надёжность и регион. Неподходящие предложения скрыты; включите «Показать неподходящие», чтобы увидеть их с причинами. Требования: от 12 ГБ VRAM (рекомендуется 16+), CUDA 12.8+, подтверждённая цена. Нажмите **Выбрать · ID …**: Offer ID подставится сам.
2. **Создать GPU-сервер.** Проверьте цену GPU в час, оценку стоимости на 1, 3 и 8 часов и строку о хранении диска. Если API не сообщает стоимость хранения, это написано прямо: проверьте её в панели CloudCompute. Размер диска по умолчанию — 80 ГБ: образ занимает около 13 ГБ, к этому добавляются модели и кеш. Отметьте «Понимаю: оплата начинается сразу…» и подтвердите окно с ценой. Без отметки и подтверждения платный запрос не отправляется.
3. **Инициализировать движок.** Начинается автоматически сразу после создания. Этапы: GPU-сервер создан → инстанс запускается → образ Docker готов → YOISAKI ENGINE запускается → проверка движка → GPU готов. Каждый этап отмечается только по фактическому сигналу: статусу из API CloudCompute или этапу, подписанному токеном движка. Первый запуск занимает примерно 10–25 минут, так как скачивается образ 4,6 ГБ. Кнопка возобновляет наблюдение, например после перезапуска приложения или по истечении времени ожидания.
4. **Подключить.** Выполняется автоматически, когда GPU сообщает защищённый адрес. Вручную кнопка нужна, если в этот момент было подключено что-то другое. Адрес и токен вводить не нужно.
5. **Синхронизировать модели.** После «GPU готов» приложение само передаёт этому GPU доступ к выбранной папке Google Drive только на чтение. Затем сравнивает папку с моделями на диске GPU. Если при создании была отмечена соответствующая опция, скачиваются отсутствующие и изменённые файлы **из числа выбранных** в «Модели → Google Drive» (с 1.7.6; без выбора автоматически ничего не скачивается — см. `docs/MODEL_LIBRARY_ANDROID_RU.md`). Уже установленные не скачиваются повторно, каждый файл проверяется, после чего список моделей обновляется. Кнопка повторяет проверку и загрузку.

После этого откройте **Генерация**.

## Деньги

- Оплата начинается сразу после создания и идёт, пока инстанс существует.
- «Отключиться», закрытие приложения и выключение телефона оплату **не** останавливают.
- Остановка инстанса выполняется в панели CloudCompute (кнопка «Открыть панель CloudCompute»): в опубликованном API нет команды остановки GPU-инстанса. Хранение диска может оплачиваться и у остановленного инстанса.
- «Удалить инстанс» в списке инстансов прекращает оплату и удаляет его диск. Модели в Google Drive остаются. Удаление требует ввести ID.
- Приложение никогда не создаёт инстанс без вашего подтверждения, не повторяет платный запрос автоматически и не удаляет данные само.
- Если цена изменилась между выбором и созданием, создание отклоняется и показывается новая цена. Предел цены, переданный в CloudCompute, равен подтверждённой цене.

## Расширенные настройки

- **Расширенные настройки запуска:** другой Docker-образ движка, отключение проверки публичности образа (только для собственного реестра), подготовка существующего инстанса. Для инстанса, созданного не здесь, выдаётся одна команда для веб-терминала инстанса в панели CloudCompute. Её вставляют один раз; она содержит новый токен движка, не публикуйте её.
- **Ручное создание по Offer ID:** прежняя форма 1.7.4 (Offer ID, образ, диск, предел цены). Движок она не запускает.
- **Подключение CloudCompute по ссылке:** прежнее ручное подключение по URL и токену.
- «Забыть сервер на телефоне» удаляет только запись на телефоне. Инстанс в CloudCompute остаётся и оплачивается.

## Как это устроено и что хранится где

| Что | Где |
|---|---|
| API-ключ CloudCompute | только телефон, `secrets.json` 0600; на GPU не передаётся |
| Токен движка (новый для каждого сервера) | телефон `secrets.json` 0600; GPU `/data/config/engine/engine.token` 0600; поле `onstart` инстанса в CloudCompute (видно владельцу аккаунта и провайдеру) |
| Доступ Google Drive | телефон; GPU получает его по защищённому туннелю с токеном движка только после подключения. Область — `drive.readonly` |
| Адрес движка | GPU публикует его в ntfy.sh в канале, производном от токена, с HMAC-подписью; сам токен не публикуется, а поддельные записи отбрасываются |

Механизм: при создании приложение передаёт документированное поле `onstart` — короткий скрипт запуска. Внутри опубликованного образа он вызывает `cloudcompute/autostart-image.sh`: тот сохраняет токен, запускает движок от непривилегированного пользователя (uid 1000) и следит за ним. Если инстанс оказался виртуальной машиной с Docker, тот же скрипт скачивает и запускает образ с `--gpus all` и постоянной папкой данных. Движок проходит проверку GPU/CUDA, поднимает Cloudflare Quick Tunnel и публикует подписанный адрес. Приложение находит адрес, проверяет токен и версию движка и подключается. После перезапуска GPU адрес меняется; сохранённое подключение находит новый адрес само.

Если CloudCompute не выполнит `onstart` для этого образа, этапы после «Инстанс запускается» не появятся. Через 60 минут приложение сообщит об этом, напомнит, что оплата продолжается, и предложит открыть журнал инстанса в панели: `/var/log/yoisaki-onstart.log` или `/tmp/yoisaki-onstart.log`. Обходной путь без SSH: **Подготовить уже существующий инстанс** и одна команда в веб-терминале панели.

Внутри: YOISAKI ENGINE 1.7.0 без изменений (SDXL / Illustrious XL, Multi-LoRA, ControlNet, Regional Control, Img2Img, исправления памяти), torch 2.10.0+cu128, diffusers 0.36.0, cloudflared 2026.9.3, rclone. Моделей, ключей и учётных данных Google в образе нет.

Публикация новой версии: измените `cloudcompute/VERSION` и метку `org.opencontainers.image.version` в Dockerfile, затем отправьте коммит в GitHub. `.github/workflows/engine-image.yml` соберёт и опубликует `engine:<версия>`. Уже опубликованную версию workflow не перезаписывает. Тег `latest` не используется. Собственная копия репозитория: Settings → Actions → General → Workflow permissions → Read and write. После первой публикации проверьте Packages → engine → Package settings → Visibility = Public (CloudCompute не скачивает приватные образы); итог проверки виден в Summary запуска. Lock-файл зависимостей пересоздаётся командой из `scripts/lock-engine-deps.py`.
