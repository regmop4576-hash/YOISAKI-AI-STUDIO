# YOISAKI AI STUDIO 1.7.7 — CloudCompute без терминала

Для уже настроенной установки на Android (сайт работает, ключ CloudCompute сохранён, Google подключён, папка моделей выбрана). SSH, Python, pip и команды Termux при обычной работе не нужны. Отчёты 1.7.7: `YOISAKI_GPU_MONITOR_REPORT.md`, `YOISAKI_DOCKER_AUDIT.md`, `YOISAKI_V1.7.7_TEST_RESULTS.md`.

## Обычный запуск GPU

Откройте **GPU → CloudCompute**. Под полем API-ключа находится блок **CLOUDCOMPUTE** с шестью шагами и **МОНИТОРОМ GPU**.

1. **Найти GPU.** Приложение запрашивает у CloudCompute список предложений (`GET /offers`, официальный API). Фильтры по умолчанию: 1 GPU, VRAM от 16 ГБ (желательно 24 ГБ — отмечается ★), цена GPU до 30 ₽/ч, диск от 60 ГБ, указанная версия CUDA (образу нужна 12.8+). Фильтры и сортировка меняются в «Фильтры». «Автообновление» опрашивает CloudCompute с безопасным интервалом (от 30 с, по умолчанию 1 мин), уважает ограничение частоты (HTTP 429, Retry-After) и само выключается через 2 часа; кнопка «Остановить мониторинг» останавливает его сразу. О новом подходящем предложении приложение сообщает один раз (в приложении и, если разрешено, уведомлением браузера). **Арендовать что-либо автоматически приложение не будет никогда.**
2. **Проверить предложение.** Нажмите **Выбрать · ID …**, затем «Проверить предложение в CloudCompute»: приложение заново получает данные CloudCompute и показывает итоговую конфигурацию — GPU, VRAM, цену в час, оценку на 1/3/8 ч, диск и предел предложения, хранение диска, образ и его доступность, профиль инициализации, размер скрипта запуска. Проверка **не резервирует** GPU.
3. **Подтвердить аренду.** Отметьте «Понимаю: оплата начинается сразу…» и подтвердите окно с ценой. Перед платным запросом предложение перепроверяется ещё раз. Если CloudCompute отвечает, что хост уже занят, показывается его точный ответ, предложение помечается «ЗАНЯТ», список обновляется (фильтры сохраняются) и предлагаются другие подходящие варианты. Повторная отправка автоматически не выполняется; повторное нажатие той же формы не создаёт второй сервер. Если ответ CloudCompute потерян (таймаут), приложение не считает, что сервер не создан: оно ищет его в списке инстансов и не даст создать новый, пока это не выяснено.
4. **Инициализировать движок.** Начинается автоматически. Этапы (каждый — только по факту): инстанс создан в CloudCompute → CloudCompute готовит хост → CloudCompute готовит образ → **инстанс CloudCompute работает** → контейнер YOISAKI запущен → YOISAKI ENGINE запускается → проверка состояния движка → **YOISAKI ENGINE готов**. Две плитки показывают отдельно «Инстанс CloudCompute» (статус провайдера как есть) и «YOISAKI ENGINE» (готов только после проверки состояния). При сбое указано, где он: CloudCompute, Docker на хосте, драйвер/NVIDIA Container Toolkit, инициализация инстанса (onstart/профиль), движок (Python), проверка GPU или связь. Первый запуск — примерно 10–25 минут (образ 4,6 ГБ).
5. **Подключить.** Выполняется автоматически, когда GPU сообщает защищённый адрес.
6. **Синхронизировать модели.** После «YOISAKI ENGINE готов» приложение передаёт GPU доступ к выбранной папке Google Drive только на чтение и скачивает отсутствующие **выбранные** модели (см. `docs/MODEL_LIBRARY_ANDROID_RU.md`).

**Скачать диагностику (JSON)** сохраняет `YOISAKI_CLOUDCOMPUTE_DIAGNOSTICS.json`: версии, ID инстанса, статус провайдера, этапы с временем, коды ошибок, результат проверки движка. Ключа CloudCompute, токена движка, токенов Google и SSH-ключей в файле нет. **Проверить веб-терминал** показывает, доступен ли терминал инстанса (например, «Terminal port has not yet been published by the host.»); при профиле `worker` терминала может не быть — это не ошибка движка.

После этого откройте **Генерация**.

## Деньги

- Оплата начинается сразу после создания и идёт, пока инстанс существует.
- «Отключиться», закрытие приложения и выключение телефона оплату **не** останавливают.
- Остановка инстанса выполняется в панели CloudCompute (кнопка «Открыть панель CloudCompute»): в опубликованном API нет команды остановки GPU-инстанса. Хранение диска может оплачиваться и у остановленного инстанса.
- «Удалить инстанс» в списке инстансов прекращает оплату и удаляет его диск. Модели в Google Drive остаются. Удаление требует ввести ID.
- Приложение никогда не создаёт инстанс без вашего подтверждения, не повторяет платный запрос автоматически и не удаляет данные само.
- Если цена изменилась между выбором и созданием, создание отклоняется и показывается новая цена. Предел цены, переданный в CloudCompute, равен подтверждённой цене.

## Расширенные настройки

- **Расширенные настройки запуска:** другой Docker-образ движка, отключение проверки публичности образа (только для собственного реестра), подготовка существующего инстанса. Для инстанса, созданного не здесь, выдаётся одна команда для веб-терминала инстанса в панели CloudCompute. Её вставляют один раз; она содержит новый токен движка, не публикуйте её.
- **Ручное создание по Offer ID:** прежняя форма 1.7.4 (Offer ID, образ, диск, предел цены). Движок она не запускает.
- **Подключение CloudCompute по ссылке:** прежнее ручное подключение по URL и токену.
- «Забыть сервер на телефоне» удаляет только запись на телефоне. Инстанс в CloudCompute остаётся и оплачивается.

## Как это устроено и что хранится где

| Что | Где |
|---|---|
| API-ключ CloudCompute | только телефон, `secrets.json` 0600; на GPU не передаётся |
| Токен движка (новый для каждого сервера) | телефон `secrets.json` 0600; GPU `/data/config/engine/engine.token` 0600; поле `onstart` инстанса в CloudCompute (видно владельцу аккаунта и провайдеру) |
| Доступ Google Drive | телефон; GPU получает его по защищённому туннелю с токеном движка только после подключения. Область — `drive.readonly` |
| Адрес движка | GPU публикует его в ntfy.sh в канале, производном от токена, с HMAC-подписью; сам токен не публикуется, а поддельные записи отбрасываются |

Механизм: при создании приложение передаёт документированные поля `template_image`, `bootstrap_profile` (по умолчанию `worker`; меняется в «Расширенных настройках») и `onstart` — короткий скрипт запуска (≈1,1 КБ из бюджета 8 КБ при общем лимите 16 384 байта). Внутри образа он вызывает `cloudcompute/autostart-image.sh --provision`: тот сохраняет токен (0600), запускает движок от непривилегированного пользователя (uid 1000) и следит за ним. С 1.7.7 автоматический скрипт не запускает Docker внутри инстанса (вложенный Docker CloudCompute не документирует); вариант для хоста с Docker остался только в ручной команде «Подготовить уже существующий инстанс» и срабатывает лишь при доступном демоне Docker. Движок проходит проверку GPU/CUDA, поднимает Cloudflare Quick Tunnel и публикует подписанный адрес. Приложение находит адрес, проверяет токен и версию движка и подключается.

Если CloudCompute сообщает «running», а контейнер YOISAKI за 15 минут ни разу не отозвался, приложение пишет об этом прямо («Инстанс работает, движок — нет»); через 60 минут — таймаут с указанием вероятного места сбоя и напоминанием, что оплата продолжается. Журналы на инстансе: `/var/log/yoisaki-onstart.log` или `/tmp/yoisaki-onstart.log`, `/data/logs/autostart.log`, `/data/logs/server.log`.

## Образ движка

`ghcr.io/regmop4576-hash/yoisaki-ai-studio/engine:1.7.7` — публичный (анонимная загрузка проверена), linux/amd64. Digest: `sha256:c10d8d6dcd179020850cece5fe937a25032e78804d99277a10a1d426466d1fcd`. Внутри: YOISAKI ENGINE 1.7.0 без изменений, torch 2.10.0+cu128 (ядра sm_70 sm_75 sm_80 sm_86 sm_90 sm_100 sm_120), diffusers 0.36.0, cloudflared 2026.9.3, rclone. Отличия от 1.7.5: контейнер стартует от root (движок по-прежнему работает от uid 1000), CMD образа не завершается при гонке с onstart, проверка GPU принимает RTX 4090/Ada (sm_89). Образ 1.7.5 оставлен в реестре без изменений. Подробно: `YOISAKI_DOCKER_AUDIT.md`. Моделей, ключей и учётных данных Google в образе нет.

Публикация новой версии: измените `cloudcompute/VERSION` и метку `org.opencontainers.image.version` в Dockerfile, затем отправьте коммит в GitHub. `.github/workflows/engine-image.yml` соберёт и опубликует `engine:<версия>`. Уже опубликованную версию workflow не перезаписывает. Тег `latest` не используется. Собственная копия репозитория: Settings → Actions → General → Workflow permissions → Read and write. После первой публикации проверьте Packages → engine → Package settings → Visibility = Public (CloudCompute не скачивает приватные образы); итог проверки виден в Summary запуска. Lock-файл зависимостей пересоздаётся командой из `scripts/lock-engine-deps.py`.
