# YOISAKI AI STUDIO 1.7.6 — модели Google Drive и монитор синхронизации (Android)

Для установки, где сайт уже работает в Termux и Google подключён. SSH, команды Termux, rclone authorize и повторный вход в Google не нужны.

Раздел **Модели** теперь состоит из трёх частей. Над ними — блок **CLOUDCOMPUTE · СОСТОЯНИЕ** и блок **Аккаунт и папка**.

| Вкладка | Что показывает | Нужен GPU? |
|---|---|---|
| **GOOGLE DRIVE** | Файлы моделей в выбранной папке Google Drive | Нет |
| **МОДЕЛИ GPU** | Модели, реально установленные на подключённом GPU. Без GPU — сохранённый список с пометкой «кеш, недоступна» | Да, для актуальных данных |
| **СИНХРОНИЗАЦИЯ** | Перенос Google Drive → CloudCompute в реальном времени и сравнение двух источников | Да, для загрузки |

## Сценарий A — без GPU

1. Откройте **Модели**. Без подключённого GPU сразу откроется вкладка **GOOGLE DRIVE**.
2. В блоке **Аккаунт и папка** видны аккаунт и папка моделей. Если папка не выбрана, нажмите **Выбрать папку**. Выбранная папка не сбрасывается на корень Диска.
3. Нажмите **ПРОВЕРИТЬ GOOGLE DRIVE**. Приложение:
   - проверяет вход в Google и обновляет токен;
   - проверяет папку;
   - читает список файлов, включая вложенные папки;
   - сохраняет время проверки.

   Метка **Проверено онлайн** означает свежую проверку. **Сохранённый список** — прежний результат, не подтверждённый сейчас.
4. Для каждого файла показаны:
   - имя, размер, папка, дата изменения;
   - контрольная сумма Google Drive (sha256, sha1 или md5) и ревизия;
   - тип и статус «☁️ Доступна на Google Drive».

   Тип определяется по папке, как у движка: `checkpoints/`, `loras/`, `vae/`, `controlnet/`. Архитектура до чтения заголовка показывается как «не проверена».
5. **Определить типы** (или **Определить тип** у файла) читает только заголовок `.safetensors`: обычно от нескольких до сотен килобайт, веса модели не скачиваются. После чтения показаны:
   - архитектура (SDXL) и совместимость по правилам движка;
   - базовая модель из метаданных;
   - соответствие размера файла заголовку (обнаруживает недокачанный на Drive файл).
6. Отметьте нужные модели. Есть фильтры CHECKPOINTS / LORA / VAE / CONTROLNET / ДРУГОЕ, поиск, **Выбрать все** и **Снять выбор**. Выбор сразу сохраняется на телефоне. Блок **ВЫБОР ДЛЯ СИНХРОНИЗАЦИИ** показывает:
   - сколько скачать;
   - сколько места нужно на диске GPU (с резервом 2 ГБ);
   - хватит ли планового диска сервера (образ движка занимает около 13 ГБ).
7. **По папкам** — просмотр папок Google Drive:
   - вложенные папки, поиск в папке, кнопка «Ещё файлы» для больших папок;
   - кнопка ↑ ведёт к родительским папкам. Выше выбранной папки — только просмотр, выбор папки не меняется.

Отметить нельзя файлы, которые GPU всё равно не примет. Причина видна рядом с файлом:

- `.ckpt`, `.pt`, `.pth`, `.bin`: движок не загружает pickle;
- файлы вне `checkpoints/`, `loras/`, `vae/`;
- ControlNet: движок 1.7.0 берёт ControlNet из Hugging Face;
- несовместимые по заголовку файлы;
- повреждённые файлы;
- файлы, которые владелец запретил скачивать.

## Сценарий B — с GPU

1. Подключите GPU на странице **GPU** (кнопки CloudCompute из 1.7.5).
2. Метка **ГОТОВ К ГЕНЕРАЦИИ** появляется только после успешной проверки состояния движка YOISAKI ENGINE и при наличии совместимого checkpoint. Сохранённого ключа CloudCompute для неё недостаточно.
3. После «GPU готов» приложение передаёт GPU доступ к папке только на чтение и сравнивает файлы. Затем автоматически скачивает **только выбранные** модели. Если ничего не выбрано, автоматически ничего не скачивается, и об этом выводится сообщение. Вручную:
   - **Синхронизация → Синхронизировать выбранные (N)**;
   - **Все недостающие** (после подтверждения).
4. Монитор **GOOGLE DRIVE → CLOUDCOMPUTE** показывает:
   - этап на русском и английском;
   - текущий файл;
   - байты и процент;
   - скорость;
   - оставшееся время;
   - число готовых и оставшихся файлов.

   Все числа приходят от процесса загрузки на GPU. Пока скорость неизвестна, вместо неё написано «Вычисляется…» или «Недоступно».
5. После завершения:
   - список моделей GPU обновляется;
   - блок **ПРОВЕРКА КАТАЛОГА GPU** показывает по каждому новому файлу: «доступна в генераторе», «совместимость не подтверждена», «несовместима» (с причиной) или «не найдена в каталоге»;
   - новые LoRA появляются в генераторе без перезапуска движка.

## Этапы синхронизации

| Этап | Значение |
|---|---|
| ОЖИДАНИЕ · IDLE | Задания нет |
| ОЖИДАНИЕ GPU · WAITING FOR GPU | Модели выбраны, GPU не подключён |
| ЧТЕНИЕ GOOGLE DRIVE · CHECKING DRIVE | GPU читает список папки |
| СРАВНЕНИЕ ФАЙЛОВ · COMPARING FILES | Сравнение с моделями на диске GPU |
| ЗАГРУЗКА · DOWNLOADING | Идёт передача (или проверка частичной загрузки перед продолжением) |
| ПРОВЕРКА · VERIFYING | Контрольная сумма, проверка safetensors, атомарная установка |
| ЗАВЕРШЕНО · COMPLETED | Все файлы задания проверены и установлены |
| ОТМЕНЕНО · CANCELLED | Отменено. Частичный файл сохранён для продолжения |
| ОШИБКА · ERROR | Подписано: **Ошибка синхронизации**, **Ошибка доступа Google Drive** или **Ошибка связи с GPU**, и что сделать |

Модель считается готовой только после проверки. Частично загруженный файл хранится отдельно (`.yoisaki-sync/*.part`) и в списке моделей не появляется. **Повторить** продолжает загрузку с места остановки. Уже установленные файлы заново не скачиваются.

## Телефон заблокирован, вкладка закрыта, связь пропала

Загрузка идёт на GPU, а не на телефоне. Номер задания и последнее состояние сохраняются на телефоне. После перезагрузки страницы или перезапуска Termux монитор:

1. сразу показывает последнее известное состояние (с пометкой);
2. запрашивает у GPU текущее.

Загрузка при этом не начинается заново. Если GPU не отвечает, это написано прямо: «Связь с GPU потеряна… синхронизация на GPU продолжается без телефона».

## Деньги

- GPU оплачивается, пока существует инстанс. «Отключиться», закрытие сайта и выключение телефона оплату **не** останавливают.
- Красные предупреждения с кнопкой **Открыть панель CloudCompute** появляются, если:
  - движок не запустился;
  - CUDA не прошла проверку;
  - Google отклонил доступ на GPU;
  - синхронизация не может начаться;
  - синхронизация дважды подряд закончилась ошибкой.
- Приложение не удаляет инстансы само и не создаёт платные серверы повторно.

## Ошибки Google Drive

| Сообщение | Что делать |
|---|---|
| Доступ истёк | «Сменить Google-аккаунт» → войти снова. Папка останется выбранной |
| Нет прав доступа | Папка или файл не открыты подключённому аккаунту (доступ `drive.readonly`) |
| Папка не найдена | Папка удалена или в корзине: выберите папку заново |
| Нет связи | Проверьте интернет. Показан сохранённый список с пометкой |
| Лимит Google | Повторите позже |

## Ограничения 1.7.6

- Живой Google Drive и живой GPU CloudCompute в разработке не проверялись. См. отчёт `YOISAKI_V1.7.6_REPORT_RU.md`.
- Синхронизация переносит `checkpoints/`, `loras/`, `vae/` (до двух подпапок, только `.safetensors`, до 2000 файлов в папке). Так работает GPU-часть 1.7.5, она не менялась.
- ControlNet-файлы из Drive видны, но не синхронизируются: генератор берёт ControlNet из Hugging Face.
- Совместимость по заголовку — те же правила, что у движка. VAE и LoRA без метаданных базовой модели отмечаются как «не подтверждена», а не как совместимые.
