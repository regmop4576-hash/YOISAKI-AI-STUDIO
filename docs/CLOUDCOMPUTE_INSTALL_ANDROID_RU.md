# YOISAKI ENGINE на CloudCompute — установка с Android-телефона

Версия: **CloudCompute deployment 1.7.1** (протокол движка 1.7.0, тот же, что в Colab).
Сайт YOISAKI AI STUDIO v1.7.1 CLOUDCOMPUTE EDITION работает в Termux на телефоне как раньше. Меняется только место, где работает GPU-движок.

```
Android → Termux → YOISAKI AI STUDIO → туннель Cloudflare (HTTPS) → CloudCompute GPU → YOISAKI ENGINE
```

Google Colab остаётся рабочим вариантом: блокнот `colab/YOISAKI_ENGINE_V1.7.0_IMG2IMG_EDITION.ipynb` сохраняет тот же протокол; встроенные метаданные движка обновлены синхронно с engine/.

**Обозначения в командах:**

- 📱 **TERMUX** — команду вводят в Termux на телефоне;
- 🖥 **СЕРВЕР** — команду вводят на GPU-сервере CloudCompute (через SSH из Termux или в веб-терминале CloudCompute).

> ⚠ **На реальном GPU CloudCompute эта сборка ещё не запускалась.** Всё, что можно проверить без GPU, проверено. Перечень проверок для первого запуска — в разделе 16.

## 1. Подготовка аккаунта CloudCompute

1. Зарегистрируйтесь на https://cloudcompute.ru и пополните баланс.
2. Оплата почасовая. Деньги списываются, пока инстанс существует, а не только пока идёт генерация. Подробнее — раздел 14.
3. Подготовьте SSH-ключ (если доступ к серверу будет через SSH). Это делается один раз:

📱 **TERMUX**
```bash
pkg update -y && pkg install -y openssh
ssh-keygen -t ed25519 -f ~/.ssh/id_ed25519 -N ""
cat ~/.ssh/id_ed25519.pub
```

Скопируйте строку, которая начинается с `ssh-ed25519`, и вставьте её в настройки SSH-ключей CloudCompute или при создании инстанса. Это **публичный** ключ, его можно передавать. Файл `~/.ssh/id_ed25519` без `.pub` — секретный, никому не отправляйте.

## 2. Выбор GPU

| GPU | VRAM | Архитектура | Поддержка в этой сборке |
|---|---|---|---|
| **RTX 5060 Ti** (основной вариант) | 16 ГБ | Blackwell, sm_120 | да: PyTorch 2.10 + CUDA 12.8 содержит ядра sm_120 |
| RTX 3060 | 12 ГБ | Ampere, sm_86 | да; 12 ГБ хватает благодаря CPU Offload, но запас меньше |
| RTX 3090 / RTX A5000 | 24 ГБ | Ampere, sm_86 | да |
| Tesla T4 | 16 ГБ | Turing, sm_75 | да (та же карта, что в Colab) |

- Для RTX 50xx (в том числе 5060 Ti) драйвер NVIDIA на сервере должен поддерживать CUDA 12.8. Это драйвер версии 570 или новее. Версию драйвера показывает `nvidia-smi` (раздел 13).
- Совместимость скрипт проверяет сам перед каждым запуском. Он смотрит, есть ли в PyTorch ядра для этого GPU, и выполняет пробное fp16-вычисление. Если проверка не прошла, движок не запускается, чтобы вы не платили за неработающий сервер.

**Системная RAM:** минимум 16 ГБ, лучше 32 ГБ. При CPU Offload веса SDXL лежат в обычной RAM и подгружаются в VRAM по частям.

## 3. Диск

- Минимум **50 ГБ**, лучше **100 ГБ и больше**. Из чего складывается объём:
  - SDXL / Illustrious XL checkpoint — около 6–7 ГБ каждый;
  - LoRA;
  - ControlNet: OpenPose, Canny, Depth;
  - SDPose-OOD;
  - кэш Hugging Face;
  - зависимости: PyTorch с CUDA, несколько ГБ;
  - образ Docker, если сервер работает в режиме Docker.

  Точные размеры загрузок печатает `fetch-models-cloudcompute.sh` перед скачиванием.
- Все данные YOISAKI хранятся в **одной папке**: по умолчанию `/workspace/yoisaki-data`. Её нужно разместить на диске, который сохраняется при остановке инстанса. Как это проверить — раздел 8.

## 4. Создание GPU-инстанса

1. В панели CloudCompute выберите конфигурацию с подходящим GPU (раздел 2), RAM и диском (раздел 3).
2. Добавьте SSH-ключ из раздела 1.
3. Если CloudCompute предлагает выбрать образ или шаблон, возьмите обычный Linux x86_64 с драйвером NVIDIA: Ubuntu, шаблон PyTorch/CUDA или шаблон с Docker. Подходят оба варианта, скрипт сам выберет режим (раздел 6).
4. Запишите адрес сервера, порт SSH и имя пользователя из карточки инстанса.

> Режим тарификации (on-demand или interruptible) по FAQ CloudCompute выбирается при создании, и изменить его потом нельзя. Interruptible-инстанс может быть прерван в любой момент.

**Способ 2 — прямая ссылка на ZIP** (например, на файл в вашем репозитории GitHub):

🖥 **СЕРВЕР**
```bash
mkdir -p /workspace && cd /workspace
curl -fL -o YOISAKI_AI_STUDIO_V1.7.1_CLOUDCOMPUTE_EDITION.zip 'ПРЯМАЯ_ССЫЛКА_НА_ZIP'
```

Распакуйте пакет:

🖥 **СЕРВЕР**
```bash
cd /workspace
unzip -q YOISAKI_AI_STUDIO_V1.7.1_CLOUDCOMPUTE_EDITION.zip
mv YOISAKI_AI_STUDIO_V1.4.0_LOCAL_EDITION yoisaki-app
cd /workspace/yoisaki-app
```

Внутренняя папка архива называется `YOISAKI_AI_STUDIO_V1.4.0_LOCAL_EDITION`, как во всех версиях: так устроена совместимость `update.sh`.

**Первый запуск:**

🖥 **СЕРВЕР**
```bash
cd /workspace/yoisaki-app
./start-cloudcompute.sh
```

Скрипт сам выбирает режим:

- **Docker** — если на сервере есть Docker с поддержкой NVIDIA. Образ собирается один раз; модели в образ не входят.
- **native** — если Docker нет. Это обычный случай, когда сам инстанс уже является контейнером. Python-окружение ставится один раз в `/workspace/yoisaki-data/runtime/venv`.

Режим можно задать вручную: `./start-cloudcompute.sh --mode native` или `--mode docker`.

Первый запуск скачивает PyTorch и зависимости: это несколько ГБ и заметное время. Следующие запуски ничего не переустанавливают.

Если моделей ещё нет, движок запустится и предупредит, что checkpoint не найден. Загрузите модели (раздел 7) и на сайте нажмите «Обновить» на странице GPU: перезапуск не нужен.

## 7. Модели: где лежат и как их загрузить

Структура совпадает с папкой Google Drive `MyDrive/YOISAKI_AI_STUDIO/`:

```
/workspace/yoisaki-data/
├── models/
│   ├── checkpoints/      ← SDXL / Illustrious XL (.safetensors)
│   ├── loras/            ← LoRA (.safetensors, рядом можно положить .json с trigger words)
│   ├── vae/
│   └── controlnet/
├── huggingface-cache/    ← ControlNet, SDPose-OOD, препроцессоры, конфиги SDXL (скачиваются автоматически)
├── sdpose/               ← необязательно: локальная копия SDPose-OOD (unet/, vae/, decoder/)
├── outputs/              ← временные результаты до сохранения в галерею сайта
├── logs/                 ← журналы движка и туннеля
├── diagnostics/          ← memory.jsonl, startup-timings.jsonl, отчёт проверки
├── config/yoisaki.env    ← необязательные настройки и токены
└── runtime/              ← Python-окружение, cloudflared, служебное состояние
```

**Загрузка моделей.** Существующие файлы никогда не перезаписываются. Перед загрузкой проверяется свободное место. Прерванная загрузка продолжается при повторе той же команды.

🖥 **СЕРВЕР**
```bash
cd /workspace/yoisaki-app

# 1) Из Google Drive. В Drive: файл → «Поделиться» → «Все, у кого есть ссылка».
./fetch-models-cloudcompute.sh gdrive 'https://drive.google.com/file/d/ID_ФАЙЛА/view' --kind checkpoint --name illustriousXL.safetensors
./fetch-models-cloudcompute.sh gdrive 'https://drive.google.com/file/d/ID_ФАЙЛА/view' --kind lora --name my_lora.safetensors

# 2) По прямой ссылке (Hugging Face, Civitai и т. п.)
./fetch-models-cloudcompute.sh url 'https://…/model.safetensors' --kind checkpoint

# 3) Заранее скачать ControlNet / SDPose-OOD / препроцессоры в постоянный кэш (необязательно)
./fetch-models-cloudcompute.sh prefetch

# Что уже лежит в каталоге
./fetch-models-cloudcompute.sh list
```

- Без `prefetch` эти файлы скачаются при первом использовании ControlNet или SDPose, как в Colab, и останутся в кэше.
- Для закрытых моделей (Civitai, gated HF) токены записываются в файл настроек, а не в команду. Иначе они попадут в историю оболочки.

🖥 **СЕРВЕР**
```bash
cp /workspace/yoisaki-app/cloudcompute/yoisaki.env.example /workspace/yoisaki-data/config/yoisaki.env
chmod 600 /workspace/yoisaki-data/config/yoisaki.env
nano /workspace/yoisaki-data/config/yoisaki.env     # заполните HF_TOKEN= / CIVITAI_TOKEN=
```

Файл с телефона тоже можно передать: `scp -P ПОРТ ~/storage/downloads/model.safetensors ПОЛЬЗОВАТЕЛЬ@АДРЕС:/workspace/yoisaki-data/models/checkpoints/`. Через мобильный интернет это медленно.

## 8. Постоянное хранилище: проверка

Данные переживают перезапуск, только если папка данных лежит на сохраняемом диске инстанса.

- Документация CloudCompute (FAQ) говорит, что остановленный инстанс не уничтожается, данные остаются, а хранение продолжает оплачиваться.
- **Удаление инстанса** может безвозвратно удалить его диск вместе с моделями.

Проверьте поведение на своём инстансе один раз:

🖥 **СЕРВЕР**
```bash
df -h /workspace/yoisaki-data           # на каком диске лежит папка и сколько места
cat /workspace/yoisaki-data/.yoisaki-data-id
```

Остановите и снова запустите инстанс в панели CloudCompute. Если файл `.yoisaki-data-id` на месте и в нём та же дата создания, папка сохраняется.

Если `/workspace` не сохраняется, а постоянный диск смонтирован в другом месте, укажите его перед каждой командой. Пакет приложения тоже лучше держать на постоянном диске:

🖥 **СЕРВЕР**
```bash
export YOISAKI_DATA_ROOT=/путь/на/постоянном/диске/yoisaki-data
```

## 9. Запуск движка

🖥 **СЕРВЕР**
```bash
cd /workspace/yoisaki-app
./start-cloudcompute.sh
```

Порядок запуска:

1. проверка GPU: ядра PyTorch и пробное вычисление;
2. запуск сервера движка (только на `127.0.0.1`, наружу порт не открывается);
3. туннель Cloudflare и проверка соединения через него;
4. вывод ссылки.

Пример ссылки:

```
https://xxxx-xxxx.trycloudflare.com/#token=…64 символа…
```

- **Ссылка — это ключ доступа.** Не публикуйте её и не отправляйте никому. Она меняется при каждом запуске.
- Движок работает в фоне: закрытие Termux или обрыв SSH его не останавливают.
- Показать ссылку снова: `./check-cloudcompute.sh link`.
- Модель SDXL загружается в память при первой генерации, как в Colab. Поэтому первое задание дольше. Чтобы загрузка шла ещё до показа ссылки, задайте `YOISAKI_WARMUP_CHECKPOINT=имя_файла.safetensors` в `config/yoisaki.env`. Прогрев тратит оплачиваемые секунды GPU при каждом запуске.

## 14. Безопасная остановка и оплата

Сначала остановите движок, затем **обязательно** инстанс в панели CloudCompute.

🖥 **СЕРВЕР**
```bash
cd /workspace/yoisaki-app
./stop-cloudcompute.sh
```

| Действие | Что останавливается | Оплата | Что сохраняется |
|---|---|---|---|
| Отключиться на сайте | ничего на сервере | **GPU продолжает тарифицироваться** | всё |
| `./stop-cloudcompute.sh` (движок / контейнер Docker) | движок и туннель; контейнер удаляется, образ остаётся | **GPU продолжает тарифицироваться** | модели, кэш, окружение, образ Docker |
| Остановить инстанс в панели CloudCompute | весь сервер | по FAQ CloudCompute продолжает оплачиваться **хранение** диска | диск инстанса (проверьте по разделу 8) |
| Удалить инстанс в панели CloudCompute | всё | оплата прекращается | **диск может быть удалён безвозвратно — вместе с моделями** |

- Пока инстанс существует, CloudCompute по своим правилам списывает деньги. Остановка движка экономит только VRAM, но не деньги.
- Движок **никогда не запускается сам**: нет автозапуска, у контейнера `restart: "no"`. После перезагрузки инстанса он не займёт GPU в фоне, пока вы не выполните `./start-cloudcompute.sh`.
- Скрипты не создают, не запускают и не удаляют инстансы и ничего не оплачивают. Всё это делаете только вы в панели CloudCompute.
- Перед удалением инстанса скопируйте ценное: результаты уже сохранены в галерее сайта на телефоне, а модели есть на вашем Google Drive.

## 16. Что ещё не проверено на реальном GPU (первый запуск)

На тестовой машине без GPU проверены сборка Docker-образа с установкой всех зависимостей, запуск настоящего сервера движка с имитацией CUDA, токен, health, остановка и загрузчик моделей. На реальном CloudCompute нужно один раз проверить:

1. Что выбрал `./start-cloudcompute.sh`: Docker или native, и проходит ли проверка GPU на RTX 5060 Ti (sm_120).
2. Что туннель Cloudflare создаётся с вашего инстанса (нужен исходящий интернет).
3. Text2Img и Img2Img (разделы 11–12), затем ControlNet и SDPose-OOD.
4. Что после остановки и запуска инстанса модели на месте (раздел 8).
5. Если выбран режим native: первая установка завершается, а повторный `./start-cloudcompute.sh` пишет «Зависимости уже установлены» (в среде разработки полную native-установку не дала завершить медленная сеть).
6. Время запуска по `./check-cloudcompute.sh`: этапы показываются в секундах. Заранее эти цифры не указываются: их ещё не измеряли.

Если что-то не работает, выполните `./check-cloudcompute.sh` и `./check-cloudcompute.sh logs`. Токены в выводе скрыты, поэтому его можно показать для разбора проблемы.

### Если прежняя native-установка завершилась ошибкой, но теперь пропускается

Только для этого случая удалите отметку установки (не окружение и не модели),
чтобы повторить проверенную установку. Выполнять **на GPU-сервере**, от того же
пользователя, который устанавливал пакет:

```bash
cd /workspace/yoisaki-app
./stop-cloudcompute.sh
# Если используется нестандартный диск, сначала задайте свой YOISAKI_DATA_ROOT.
rm -f -- "${YOISAKI_DATA_ROOT:-/workspace/yoisaki-data}/runtime/venv/.yoisaki-install"
./start-cloudcompute.sh --mode native
```

Для обычного исправно работающего окружения сбрасывать отметку не нужно.
Замену файлов приложения выполняйте при остановленном движке; папку данных
`yoisaki-data` сохраняйте. При установке в новую папку используйте исходное имя
ZIP и внутреннюю папку из раздела 6. Не выполняйте `mv ... yoisaki-app` поверх уже
существующего каталога: сначала выберите свободное имя для старого приложения.

После автоматического восстановления туннеля получите **новую** ссылку через
`./check-cloudcompute.sh link` и заново подключите её на странице GPU телефона.
Отрицательная проверка здоровья туннеля должна повториться трижды; обычная
краткая сетевая задержка не вызывает немедленного перезапуска.

### Что означает проверка совместимости

Одного номера ветки драйвера (например, «570») недостаточно, чтобы доказать
поддержку конкретной RTX 5060 Ti. Нужны поддержка самой карты драйвером провайдера,
совместимость CUDA runtime, успешный preflight и настоящая генерация.
Официальный список NVIDIA для 575.51.02 включает RTX 5060 Ti:
https://download.nvidia.com/XFree86/Linux-x86_64/575.51.02/README/supportedchips.html
Это пример документированной поддержки карты, а не доказательство работы вашего
инстанса или утверждение о минимально допустимом релизе.

В независимом аудите нет NVIDIA GPU и Docker daemon. Локальные тесты сервера с
имитацией CUDA и CPU-тесты Diffusers **не подтверждают** реальную GPU-генерацию,
Docker runtime, публичный Cloudflare-туннель или сохранность диска CloudCompute.
Проверки из раздела 16 остаются обязательными для приёмки реального инстанса.
Остановка движка и ошибка preflight не останавливают оплату самого инстанса.
