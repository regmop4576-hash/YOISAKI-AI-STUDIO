# YOISAKI AI STUDIO v1.7.5 — ZERO-TERMINAL CLOUDCOMPUTE

Продолжение v1.7.4 INTEGRATIONS: проект не пересоздавался. Дизайн AMBER CORE, `engine/` и Colab-блокнот побайтно совпадают с v1.7.4. Протокол движка — 1.7.0. Инструкция для пользователя: [`docs/CLOUDCOMPUTE_ZERO_TERMINAL_RU.md`](docs/CLOUDCOMPUTE_ZERO_TERMINAL_RU.md).

## Итог

Для уже настроенной установки на Android обычный запуск GPU сводится к пяти кнопкам на странице GPU: **Выбрать GPU → Создать GPU-сервер → Инициализировать движок → Подключить → Синхронизировать модели**. SSH, pip, Python и Termux для этого не нужны. Шаги 3–5 выполняются автоматически. Готовый образ движка опубликован и доступен без авторизации.

**Не проверено вживую:** создание настоящего платного инстанса и выполнение `onstart` в CloudCompute. В этой среде нет ключа пользователя, сеть к `app.cloudcompute.ru` закрыта, и платные операции не выполнялись. Всё, что относится к CloudCompute, проверено на тестовых двойниках. Первый реальный запуск — обязательная приёмка (см. «Что ещё нужно»).

## Что сделано

| Требование | Реализация |
|---|---|
| 1. Выбор GPU вместо формы | `GET /offers` (путь из официального OpenAPI, параметры не придуманы). Карточки показывают GPU, VRAM, цену в час, диск, CUDA, надёжность и регион; Offer ID подставляется сам. Есть оценка стоимости на 1/3/8 ч и отдельная строка про хранение диска. Единицы цены принимаются только из названия поля или документации: `*_minor`/`*_kopecks` — копейки, `*_rub` — рубли, `price_hour` — копейки по описанию API. Цена с неизвестными единицами показывается как «не подтверждена», и создать такой сервер одной кнопкой нельзя. Совместимость: VRAM ≥ 12 ГБ, CUDA ≥ 12.8, диск ≥ 40 ГБ. Ручной ввод Offer ID перенесён в «Расширенные настройки». |
| 2. Готовый Docker-образ | **Опубликован:** `ghcr.io/regmop4576-hash/yoisaki-ai-studio/engine:1.7.5`, digest `sha256:49a1c9519c8770cf1d99b49a13af7d3327faa8601f7781e5c5d9ee381b196fe1`, 4,57 ГБ в сжатом виде. Анонимный запрос манифеста возвращает HTTP 200. Сборка воспроизводима: base закреплён по digest, все 76 wheel — по версии и sha256 (`cloudcompute/requirements-lock.txt`, `pip install --require-hashes --no-deps`, `pip check`, `check_lock.py`), cloudflared — по sha256. Внутри: torch 2.10.0+cu128 (sm_70…sm_120), diffusers 0.36.0, transformers 4.57.3, peft 0.18.0, controlnet-aux 0.0.10, rclone. Тег версионный; workflow не перезаписывает уже опубликованную версию. Моделей, ключей и учётных данных Google в образе нет. |
| 3. Автоинициализация | Документированное поле `onstart` в `POST /instances`. Сайт генерирует новый токен движка для каждого сервера. В образе `cloudcompute/autostart-image.sh` сохраняет его (0600), запускает движок от uid 1000, ограниченно перезапускает при сбоях и применяет новый токен без второго движка. На ВМ с Docker тот же скрипт запускает образ. Лаунчер публикует подписанные этапы (ENGINE_STARTING, SERVER_READY, GPU_CHECK_FAILED…) и адрес туннеля. Сайт показывает этапы GPU CREATED → INSTANCE INITIALIZING → DOCKER IMAGE READY → ENGINE STARTING → HEALTH CHECK → GPU READY только по фактическим сигналам; через 60 минут без сигналов выдаёт явное сообщение, без выдуманного успеха. |
| 4. Автоподключение | Адрес и токен подставляются сами. Аутентификация сохранена: Bearer-токен, проверка версии и возможностей движка 1.7.0. Подключение запоминается с автопоиском нового адреса; после перезапуска приложения происходит переподключение. Ключ CloudCompute (управление арендой) и токен движка (связь) разделены, ключ на GPU не передаётся. Прямого HTTPS от CloudCompute в API нет, поэтому сохранён туннель Cloudflare. |
| 5. Google Drive | OAuth 1.7.4 и выбранная папка переиспользуются без повторной авторизации. После «GPU готов»: передача доступа `drive.readonly` этому движку по туннелю → проверка папки → только MISSING/CHANGED файлы (с выбором путей) → проверка контрольных сумм на GPU → обновление списка моделей. Полная коллекция повторно не скачивается. |
| 6. Android UX | Блок CLOUDCOMPUTE из пяти кнопок, понятные статусы, AMBER CORE; ширины 360/390/430 без горизонтальной прокрутки. Технические настройки (образ, ручной Offer ID, ручная ссылка, подготовка существующего инстанса) — в «Расширенных настройках». Существующие функции не удалены. |
| 7. Стоимость | Перед созданием видны проверенная цена в час и строка хранения (или честное «API не сообщает»). Нужны отметка «Понимаю…» и подтверждение окна с ценой. Сервер повторно читает предложение и отказывает при изменении цены, несовместимости или неопубликованном образе. Предел цены равен подтверждённой цене; повтора нет; второй сервер требует отдельного подтверждения. Данные автоматически не удаляются. Везде указано, что «Отключиться» оплату не останавливает. Есть кнопка «Открыть панель CloudCompute». |
| 8. Сохранность | Text2Img, Img2Img, ControlNet, Regional Control, Multi-LoRA, галерея, пресеты, история, Colab, исправления RAM, OAuth и ключ CloudCompute не изменены. Изменённые серверные модули: `app.mjs` (новые маршруты), `rendezvous.mjs`, `secrets.mjs` (поле deployment), `cloudcompute-api.mjs`, `provider-http.mjs` (лимит размера ответа). |

Найдено и исправлено тестами в ходе работы: (1) супервизор посылал SIGTERM подоболочке, а не лаунчеру — исправлено через `exec`; (2) в POSIX `sh` неудачная запись в `/var/log` завершала `onstart` (uid 1000) — исправлено; (3) команда для веб-терминала закрывала бы сессию из-за `exit` — теперь она обёрнута в `bash <<…`.

## Что ещё нужно (внешнее)

1. **Первый живой прогон** на дешёвом предложении: «Выбрать GPU» → «Создать». Если адаптер не распознает ответ `/offers` или `POST /instances`, будет явная ошибка `CC_RESPONSE_SCHEMA` без создания сервера и без выдуманных цен. Для доработки адаптера нужен пример ответа, без ключа.
2. Если этапы не идут дальше «Инстанс запускается», CloudCompute не выполнил `onstart` для этого образа. Используйте «Подготовить уже существующий инстанс» (одна команда в веб-терминале панели) и пришлите журнал инстанса.
3. Хранение диска и остановка инстанса — в панели CloudCompute: в API этого нет.
4. Google OAuth client — как в 1.7.4 (уже настроен у пользователя).

## Обновление на Android

```bash
cd ~/YOISAKI_AI_STUDIO_V1.4.0_LOCAL_EDITION
bash update.sh ~/storage/downloads/YOISAKI_AI_STUDIO_V1.7.5_ZERO_TERMINAL.zip
```

Укажите фактический путь к ZIP. Скрипт проверяет целостность, ставит новую версию рядом, делает резервные копии кода и данных и запускает сайт. Ключ CloudCompute, вход Google, выбранная папка, галерея и история сохраняются; повторный вход не нужен. Откройте `http://127.0.0.1:3000/engine` и убедитесь, что в настройках указано «AMBER CORE · v1.7.5 ZERO-TERMINAL CLOUDCOMPUTE EDITION».

## Откат

`update.sh` оставляет копии `~/YOISAKI_AI_STUDIO_V1.4.0_LOCAL_EDITION.backup-<дата>` и `~/.local/share/yoisaki-ai-studio.backup-<дата>`.

```bash
cd ~ && bash YOISAKI_AI_STUDIO_V1.4.0_LOCAL_EDITION/stop.sh
mv YOISAKI_AI_STUDIO_V1.4.0_LOCAL_EDITION YOISAKI_AI_STUDIO_V1.7.5.disabled
mv YOISAKI_AI_STUDIO_V1.4.0_LOCAL_EDITION.backup-<дата> YOISAKI_AI_STUDIO_V1.4.0_LOCAL_EDITION
cd YOISAKI_AI_STUDIO_V1.4.0_LOCAL_EDITION && ./start.sh
```

Данные 1.7.5 совместимы с 1.7.4: новое поле `deployment` в `secrets.json` версия 1.7.4 просто игнорирует. Восстанавливать каталог данных из копии нужно только при его повреждении. Откат приложения не удаляет и не останавливает инстансы CloudCompute: остановите или удалите их в панели, если они не нужны.
