# YOISAKI AI STUDIO v1.7.4 — технический отчёт

Исходник: предоставленный YOISAKI_AI_STUDIO_V1.7.3_ONE_CLICK_CONNECT.zip. Проект продолжен, не пересоздан. В архиве фактически React/TypeScript, esbuild и локальный Node HTTP-сервер; структура src/app сама по себе не означает работающий Next.js-сервер.

## Что исправлено

| Требование | Изменение |

UI содержит переименование, удаление и создание с подтверждением. |

## Подтверждённые причины в 1.7.3

CloudCompute REST-клиента не было. OAuth/start требовал connection, callback сразу отправлял токены на тот же GPU, а интерфейс авторизации находился внутри условия наличия GPU URL. Локальный Google-аккаунт и выбор папки отсутствовали. inventoryChanged подавлял ошибки и возвращал false, поэтому прежние модели могли выглядеть актуальными; для серверов без /inventory отсутствовало периодическое обнаружение новых файлов. Старое предупреждение «API не удалось проверить» заменено актуальным описанием.

## Что ещё требует внешней настройки и живой проверки

**Полный Google OAuth с настоящим аккаунтом не объявляется проверенным.** В поставляемом ZIP нет зарегистрированного OAuth client. Издателю необходимо создать публичный Desktop client, включить Drive API и настроить consent/проверку Google для распространения. После этого каждый GitHub-пользователь входит в свой аккаунт без отдельного OAuth-сервера и без копирования токенов. Точная настройка: `docs/INTEGRATIONS_SETUP_RU.md`. Android/Termux callback, реальные разрешения Google, refresh и скачивание приватной модели требуют живого приёмочного прогона.

**CloudCompute авторизованные ответы и платные операции не проверены живьём.** Ключ пользователя не запрашивался, аренда не создавалась. Спецификация не описывает успешные response-схемы; неизвестный формат вызывает явную ошибку адаптера. Проверка маршрута без ключа и тесты с ответами-заменителями не доказывают работу аккаунтных операций.

**Готовый Docker-образ ещё не собран/опубликован.** Workflow и путь использования реализованы, но требуют запуска в репозитории и публикации registry. CloudCompute OpenAPI не описывает управление volume mounts, поведение ENTRYPOINT/CMD и получение ссылки YOISAKI ENGINE. Поэтому универсальный первый запуск «ключ → полностью готовый генератор» не заявляется. Образ, постоянный /data, первый адрес/токен и запуск следует проверить через веб-панель провайдера. Повторное подключение использует существующий механизм сохранённых подключений, стабильного токена и rendezvous/named tunnel.

Физическая сохранность диска после остановки/пересоздания CloudCompute-инстанса, CUDA, скорость установки и генерация на настоящем GPU в этой среде не проверены. Никакие оплачиваемые облачные операции, публикация образа и действия в Google-аккаунте разработчиком не выполнялись.
