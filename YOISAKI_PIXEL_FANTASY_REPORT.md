# YOISAKI AI STUDIO v1.9.0 — PIXEL FANTASY EDITION · отчёт

Исходная точка — архив `YOISAKI_AI_STUDIO_V1.8.1_FACEFIX_PROXY_HOTFIX.zip` (сайт 1.8.1, движок 1.8.1, API 1.7.0).
До начала работ: `npm run typecheck` — OK, `npm run build` — OK, `npm test` — 153 pass / 5 skipped / 0 fail.
В git-ветке до этого лежала устаревшая Next.js-версия 1.1, поэтому первым коммитом в ветку перенесено содержимое
архива v1.8.1 без изменений (`Import YOISAKI AI STUDIO v1.8.1 … as baseline`). Все дальнейшие правки видны как diff
относительно этой версии.

**Дизайн-система Pixel Fantasy** (`src/app/globals.css`, `src/app/pixel-frames.css`, `scripts/pixel-frames.mjs`)

## 6. Исправленные ошибки и честность статусов

1. **Сброс Редактора при переходах (Редактор → Галерея → Редактор).** Режим, вкладка, классический режим,
   параметры кисти / силы / растушёвки / контекста / области и профиль Face Fix хранились в локальном `useState`
   и терялись. Теперь они в сохраняемом store (через `/api/settings` в Termux, переживают перезагрузку).
   Загруженное изображение, штрихи маски, рамка лица, результаты поиска лиц, выбор лица и последнее задание —
   в сессионном store (переходы) и в черновике IndexedDB (перезагрузка). Изображения в `localStorage` не пишутся.
   Каждый черновик привязан к `imageId`; данные для другого изображения отклоняются атомарно в одной транзакции —
   старые маски и координаты лиц не применяются к новой картинке. Отложенная запись маски сбрасывается при
   `pagehide` (найдено тестом: быстрая перезагрузка сразу после штриха теряла маску).
2. Источник Img2Img и ControlNet-референс тоже больше не теряются при переходе и перезагрузке; готовая карта
   ControlNet не сбрасывается без причины при возврате на страницу.
3. Inpaint с пустой маской теперь останавливается на клиенте с понятным сообщением (раньше уходил на GPU
   полностью чёрной маской).
4. «Залипающий» hover на Android больше не перекрывает состояния кнопок.

**Нельзя показать «GPU готов», если движок недоступен:** все индикаторы берутся из `/api/gpu/status`, который
локальный сервер формирует по проверке здоровья движка. Проверено тестом при недоступном туннеле.

**CloudCompute** по отчётам v1.7.7 / v1.7.7.1 не прошёл испытаний на реальном GPU (v1.7.7 падал на реальном
инстансе, v1.7.7.1 на GPU не проверялся). Поэтому для публичных пользователей он скрыт. Включается переключателем
«Настройки → Подключения → Показывать CloudCompute» с прямым предупреждением; если CloudCompute уже выбран на
сервере (обновление старой установки), он остаётся видимым, чтобы не отрезать пользователя от его инстанса.

## 7. Убранные и оставленные предупреждения

Убраны (устарели: функции реализованы или тексты описывали прототип), из словаря и интерфейса:

«ControlNet · Future engine», «Auto detect (coming soon)» (автопоиск лиц работает с v1.8.1), «Coming in a future

предупреждения о потере связи (неподтверждённый статус не считается завершением); удаление галереи / черновиков /
истории необратимо (подтверждение); подсказки о сохранности черт лица; предупреждение о видеопамяти; кэш моделей
при отключённом GPU; несовместимые модели с причиной от движка; все ошибки API и движка показываются как есть.

## 9. Ограничения

- **GPU-тесты не проводились.** Доступа к Colab T4 не было. Все браузерные проверки используют реальный
  локальный сервер и **синтетический** GPU (тестовые модели «TEST …», PNG-градиенты, имитация прогресса). Они не
  подтверждают реальную генерацию, качество изображений, расход VRAM и работу движка.
- Ветка Termux проверена симуляцией на Linux (как в существующих тестах), не на Android-устройстве.
  Реальная экранная клавиатура Android не проверялась (проверены размеры полей, `inputMode`, 16 px шрифт полей
  против автозума, отсутствие горизонтальной прокрутки).
- Старые браузерные сценарии `tests/v17x-*-browser.mjs` … `v181-facefix-browser.mjs` написаны под разметку v1.8.1
  (подписи кнопок, `Создать изображение` и т. п.) и в `npm test` не входят; их заменяет `v190-pixel-fantasy-browser.mjs`.
  Python-тесты движка (CPU/diffusers) не запускались: движок не менялся, а в среде нет pytest/torch.
- Компоненты Google Drive / синхронизации / CloudCompute оформлены общей дизайн-системой, но их разметка и
  тексты (пары ru/en) не перерабатывались, чтобы не трогать проверенную логику.
- Черновики редактора хранятся в IndexedDB конкретного браузера: в другом браузере на том же телефоне их не будет
  (настройки и галерея — общие, они в Termux).
