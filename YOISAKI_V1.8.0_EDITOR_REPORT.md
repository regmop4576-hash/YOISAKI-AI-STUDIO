# YOISAKI AI STUDIO v1.8.0 — EDITOR COMPLETION EDITION

Дата: 29 октября 2026, Иркутск. Сайт v1.8.0; Colab ENGINE v1.8.0; API 1.7.0.

Реализованы настоящие пути inference Inpaint и Face Fix. Проверены production-сборка, локальный HTTP/API, мобильный браузер и реальный Diffusers на маленькой SDXL со случайными весами в CPU. Полноразмерный Illustrious и Tesla T4 здесь отсутствуют: качество картинок, сохранность личности и стабильность памяти реального Colab требуют проверки на целевом GPU.

## Исходники и фактическая архитектура

Использованы именно предоставленные `YOISAKI_AI_STUDIO_V1.7.7.1_STARTUP_FIX.zip` и `YOISAKI_ENGINE_V1.7.6_COLAB_COMPATIBILITY.ipynb`. Внутри сайта — React 19, TypeScript, esbuild, Konva и существующий Node HTTP-сервер, а не исполняемый Next.js server. Сохранены структура, AMBER CORE и совместимые `next/*` адаптеры. Рабочие inference-модули Colab взяты из проверенного встроенного пакета исходного ноутбука. Отличающиеся CloudCompute-модули не подменялись Colab-вариантами.

Раньше Inpaint/Face Fix только экспортировали PNG маски и JSON рамки. Img2Img уже использовал `from_pipe` поверх загруженных SDXL-компонентов. Добавлены два специализированных модуля: `engine/inference/editor.py` и `engine/worker/resources.py`, общие для соответствующих исходников Colab и сайта. Встроенный пакет нового ноутбука содержит 27 файлов; его SHA-256 и совпадение каждого файла с Colab-исходником проверены.

## Inpaint

Загрузка → рисование Konva → промпты/модели/параметры → существующий `/generate` → настоящая `StableDiffusionXLInpaintPipeline` → композит с исходником → прежняя система результатов, истории и галереи.

Сохранены кисть, диаметр в пикселях исходника, ластик, Undo/Redo, Zoom/Pan и экспорт маски. Предпросмотр ластика исправлен: он удаляет покрытие отдельного прозрачного слоя, а не закрашивает исходник тёмным цветом. Рисование не прокручивает мобильную страницу. Маска экспортируется в полном ориентированном размере источника; белое редактируется, чёрное сохраняется, инверсии нет. Маска с иным размером отклоняется.

Добавлены Denoise, растушёвка внутрь (0–64 пикселя источника, default 8), контекстный padding (0–1, default 0.15), область `crop`/`full`. Crop обрабатывает bounding box маски с контекстом; Full использует весь источник как контекст. Выбранная область пропорционально вписывается в явно указанный рабочий размер с letterbox. После inference letterbox удаляется, область возвращается в исходный масштаб. Изменяется только поддержка исходной маски; чёрные пиксели берутся непосредственно из оригинала. Растушёвка достигает нуля на границе и не расширяет область редактирования. Если выделение слишком мало для растушёвки или рабочего разрешения, движок возвращает понятную ошибку.

## Face Fix

Сохранена ручная Konva-рамка. Работают создание, перемещение, изменение размера восемью ручками, ограничение границами и предпросмотр выбранного фрагмента. Координаты передаются в ориентированных пикселях исходника, не в экранных CSS-пикселях.

Движок проверяет рамку, расширяет контекст с учётом краёв изображения, готовит crop и маску, запускает тот же SDXL masked inference, возвращает фрагмент в исходный масштаб и плавно вклеивает его внутри выделения. Padding даёт контекст, но не разрешает менять окружающие пиксели. Отдельные реалистичные человеческие face-restorer и детекторы не загружаются.

Default Denoise — 0.25. Рабочий размер Face Fix по умолчанию 512×512, отдельно от размеров обычной генерации; пользователь видит и может менять его. Источник не обрезается и не заменяется: итог имеет полный исходный размер. Отдельная кнопка скачивает нормализованный исходник, другая — результат. Описание цвета глаз, меха, волос и мордочки задаёт пользователь; скрытые теги не добавляются. Сохранение личности не гарантировано.

## API и совместимость

Протокол `api_version=1.7.0` сохранён. `/health` дополнительно объявляет `inpaint`, `facefix` и `editor_contract=1`. Старые совместимые 1.7.0/1.7.6 остаются доступны для своих режимов. Сайт требует новые capabilities перед отправкой редакторского задания; декоративного fallback нет.

В `/generate` `kind` должен совпадать с `mode`. Существующие параметры checkpoint/VAE, промпты, LoRA/weights, seed, CFG, steps, sampler/scheduler не переписываются. Новые режимы и поля:

| Поле | Значение |
|---|---|
| mode / kind | `inpaint` или `facefix` |
| init_image | PNG/JPEG/WebP data URL |
| denoising_strength | (0, 1], минимум один реальный шаг |
| mask_image | Непрозрачный PNG, обязателен для Inpaint |
| face_region | `{x,y,width,height}`, обязателен для Face Fix |
| mask_blur | Радиус растушёвки внутрь в пикселях источника, default 8 |
| mask_padding | Доля размера выделения для контекста, default 0.15 |
| inpaint_region | `crop` (default) или `full`; Face Fix требует `crop` |
| width / height | Явный рабочий размер inference, не размер итогового источника |

Для редактора требуется batch 1. Сочетания редактора с ControlNet или Regional Control отклоняются явно; пользователь должен отключить их. Их прежние пути Text2Img/Img2Img не удалены. Автоматического изменения seed, разрешения, strength или scheduler нет. Недопустимое сочетание Euler a + Karras по-прежнему отклоняется.

Совместим установленный Diffusers 0.36.0 и выбранный base SDXL/Illustrious checkpoint с 4-канальным UNet. Используется предусмотренный Diffusers путь inpaint с base UNet, отдельный inpaint checkpoint не придуман и не скачивается. Другие архитектуры, включая 9-канальные специализированные checkpoint, этим путём не поддерживаются и не подменяются автоматически. LoRA остаются на тех же shared UNet/encoder-компонентах и выбираются с исходными весами.

## Ресурсы и безопасность

Сохранены allocator RAM FIX, CPU Offload, VAE slicing/tiling, существующий профайлер, result ACK, модельный кэш и последовательная очередь. Второй checkpoint/UNet/VAE/encoder не загружается. Перед построением editor-view снимаются hooks, `from_pipe(torch_dtype=None)` сохраняет dtype и общие компоненты; проверяются сами модули, параметры и их storage pointers на переходе. Hooks CPU Offload устанавливаются заново для нужного порядка выполнения. После задачи снимается временная view, сохраняется загруженная база; изображения/маски/conditioning освобождаются после выхода из inference. Прежняя очистка CUDA-кэша на границе освобождения wrapper сохранена; новые indiscriminate вызовы empty_cache не добавлялись.

Единственный ThreadPoolExecutor и adapter lock сериализуют все режимы, включая ControlNet preprocess. Отмена кооперативная: проверяется перед UNet и в callback; загрузка модели или выполняющийся CUDA kernel не прерываются мгновенно. Finally освобождает ресурсы при ошибке и отмене. Автоматически подтверждаются полученные результаты v1.8, в том числе при переподключении, чтобы ACK-retention не заполнял диск.

Перед inference измеряются доступная RAM, свободная/allocated/reserved VRAM, состояние модели. Проверяются только обоснованные нижние границы памяти для известных буферов и латентов: это **не** прогноз пиков UNet и не гарантия, что задание поместится. Измерения и ограничения подробно описаны в RESOURCE_REPORT.

Авторизация Bearer сохранена на GPU. Неавторизованные POST отклоняются до декодирования тела. Общий редакторский JSON ограничен 20 МиБ, каждое data URL — 8 МиБ (примерно 6 МиБ двоичных данных), входная загрузка в браузере — 25 МиБ. Проверяются MIME, сигнатура и настоящее декодирование, формат, анимация, максимум 16 Мп/8192 по стороне, соответствие размеров маски и границы лица. EXIF нормализуется перед рисованием; для внешнего API его обрабатывает Pillow. Итог сохраняет исходный alpha, включая выбранную область. Галерея/история получают digest источника и маски, без base64. Новые ресурсные логи содержат только разрешённые метрики; сообщения исключений не печатаются в tracebacks целиком с возможными приватными значениями.

## Ограничения и запуск

Реальный T4/Colab Free и полноразмерный pretrained Illustrious не проверены. CPU-тесты не доказывают качество лица, отсутствие швов на реальных сценах или отсутствие накопления RAM на T4. Ручная рамка не является автоматическим детектором. Оригинал остаётся в текущем редакторе и скачивается; повторная загрузка страницы не восстанавливает исходник автоматически. Нормализация PNG может превысить сетевой лимит: предлагается явно уменьшить исходник, без скрытого JPEG-сжатия.

Распакуйте сайт в отдельную папку. Запуск — `bash start.sh` из этой папки; действующая установка Termux может потребовать `bash install.sh`, если проверка build identity обнаружит старую сборку. Старый сайт сначала остановите через его `bash stop.sh`. Пользовательские данные старой установки не переносятся автоматически: не удаляйте её до нужного экспорта/переноса. Откройте новый приложенный notebook в Colab и используйте его защищённую ссылку. Старый notebook в `colab/` оставлен как исторический исходник; рабочая инструкция указывает v1.8.0.

После первой серии T4 выполните Text2Img → Img2Img → Inpaint → Face Fix несколько раз и скачайте последней ячейкой `YOISAKI_RESOURCES_V1.8.0.zip`. Сравните after-cleanup RSS/allocated VRAM после прогрева, проверьте OOM и восстановление после отмены. Новая ячейка не запускает дополнительные генерации.
