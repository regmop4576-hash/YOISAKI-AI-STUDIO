# YOISAKI AI STUDIO v1.8.0 — исправление установки в Termux

Это полный исправленный архив сайта. Версия приложения и протокол сохранены.

## Установка

Распакуйте ZIP в новую папку внутри домашнего каталога Termux (`~`), а не в `/sdcard` или `/storage`.
Внутренняя папка `YOISAKI_AI_STUDIO_V1.4.0_LOCAL_EDITION` имеет историческое имя для совместимости с `update.sh`; версия содержимого — 1.8.0.

В распакованной папке выполните:

```bash
bash install.sh
```

Затем запустите:

```bash
bash start.sh
```

Откройте `http://127.0.0.1:3000`. Готовая production-сборка включена: при наличии Node.js 22–26 установка не требует npm, компилятора или повторной сборки. Если Node отсутствует, сохранённая ветка Termux устанавливает nodejs-lts через pkg (нужен интернет).

Существующие настройки хранятся отдельно, обычно в `~/.local/share/yoisaki-ai-studio`. Не удаляйте этот каталог. Для обновления уже установленного сайта используйте существующий `update.sh` с путём к новому ZIP: он сохраняет данные и локальный Google Desktop OAuth client. Перед ручным запуском новой копии остановите прежнюю через `bash stop.sh` в её папке.

## Подтверждённая причина

Исходный выпущенный ZIP: SHA-256 `6e224170f08dd2dc5757edab8a1d8afe48f5cf3fe9bfbc3e48e70855b96dfe31`.

В нём устарел `package-manifest.json`: 31 неверная запись из 424, в том числе 29 несовпадающих хешей и 2 отсутствующих старых JS-ассета. Первая ошибка — `README_RU.md`.
Ожидаемый хеш: `6c2f4f1f406e27d8c4b2cd4e596ee669902919fb66720e3095d31f1afaf83555`.
Фактический хеш: `18c513d82dac14abb81d129da0d87194fb690dabebf847a6e6a2877ea4d7ea1d`.

Проверка ZIP CRC проходила; `dist/release.json` также соответствовал исходникам. Установка прекращалась раньше проверки build identity, на проверке манифеста. Ошибка воспроизведена из исходного релизного ZIP на Linux, включая ветку Termux с PREFIX; это дефект комплектации, не доказательство ошибки Android или Node.

## Исправление

- Манифест создаётся по окончательным файлам staging-папки после production build.
- Упаковщик проверяет манифест и build identity до упаковки и после повторной распаковки готового ZIP.
- Публикуется только проверенный ZIP; установочная проверка SHA-256 не отключена.
- При повреждении verifier показывает пути и ожидаемые/фактические хеши.
- Нормализация первой строки shell-скриптов для Termux сохранена; изменение команд в скрипте приводит к отказу.
- Исходники сайта, API, Google Drive, редактора и inference engine не изменены. Colab notebook не изменён.

## Повторяемые проверки

```bash
node scripts/verify-package.mjs
node scripts/build-identity.mjs
node --test tests/package-integrity.test.mjs
```

Для разработчиков на Linux: `python3 tests/release-install-smoke.py /путь/релиз.zip /путь/node` проверяет чистую и повторную установку, HTTP-запуск, обновление, сохранность синтетических настроек Google и данных. Скрипт блокирует npm/pkg, использует временные каталоги и имитирует PREFIX/interpreter path Termux. Он не является тестом на настоящем Android.

Результаты конкретных прогонов, версии Node и ограничения приведены в отдельном отчёте исправления.
