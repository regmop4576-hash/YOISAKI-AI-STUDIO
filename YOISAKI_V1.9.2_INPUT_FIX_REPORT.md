# YOISAKI AI STUDIO v1.9.2 — ANDROID INPUT FIX · отчёт

Ошибка: на Android (Brave, `http://127.0.0.1:3000`) в окне «Параметры генерации» после касания поля Width, Height
или Seed экранная клавиатура сама закрывалась, поле теряло фокус.

## Причина (найдена в коде и воспроизведена)

**1. Окно отнимало фокус у поля — первопричина.** `src/components/ui.tsx`, компонент `Modal`:

```tsx
useEffect(()=>{ const prev=document.activeElement; …
  first.focus();                       // фокус на первую кнопку окна
  return ()=>{ …; prev.focus() } },    // при очистке — фокус на прежний элемент
 [onClose]);
```

`GenerationControls` передаёт в окно `onClose={()=>setPicker('')}` — новую функцию при каждой перерисовке.
Страница «Генерация» каждые 2 секунды опрашивает `/api/history` (`setHistory` в `Generator`), и
`GenerationControls` перерисовывается (дополнительно — при любом изменении состояния GPU, на которое он подписан
целиком). Каждая перерисовка меняла `onClose` → эффект `Modal` перезапускался: очистка уводила фокус с поля,
а эффект ставил фокус на первую кнопку окна («1:1»). Поле получало `blur`, и Android закрывал клавиатуру.
Поэтому клавиатура закрывалась «во время ввода» и иногда сразу — в зависимости от момента опроса.

Воспроизведение до исправления (Chromium, эмуляция телефона 412 px, касания): через 4,5 с после касания Width
фокус оказался на кнопке «1:1», событие `blur` — 1, набранное «768» не попало в поле.

Тот же дефект затрагивал все окна на `Modal`: выбор модели и LoRA (поле поиска), просмотр галереи (заметки),
меню моделей, журнал GPU, диагностику.

**2. Преждевременное преобразование числа.** `onChange={e=>up({width:Number(e.target.value)})}`: при стирании
`Number('')` = `0`, поле сразу показывало «0» — стереть значение и набрать заново было невозможно (на Android
это выглядело как «поле не редактируется»). Та же схема была в настройках (ширина/высота по умолчанию),
Face Fix (рабочий размер), Regional Control (X/Y/W/H %), а в поле тарифа GPU нельзя было ввести «24.9» —
точка удалялась при преобразовании.

Проверено и **не является причиной**: нестабильных `key` у полей нет, поля не размонтируются (окно рендерится в
постоянной позиции), `onBlur`-обработчиков, обработчиков касаний и клавиатуры на полях не было, при изменении
высоты экрана ничего не пересоздаётся (ResizeObserver есть только у холста Редактора).

## Исправления

- `Modal` (`src/components/ui.tsx`): эффект открытия выполняется **один раз**, актуальный `onClose` хранится в
  `ref`. При открытии фокус ставится на само окно, а не на первое поле — открытие окна LoRA больше не вызывает
  клавиатуру. Возврат фокуса при закрытии — только если прежний элемент ещё на странице.
- Новый `NumberField` (`src/components/Common.tsx`): пока поле в фокусе, хранит строку — можно стереть, вставить,
  набрать «24,», «-»; число передаётся наверх, только когда строка — корректное число; при потере фокуса поле
  показывает сохранённое значение. `type="text"` + `inputMode="numeric|decimal"` даёт цифровую клавиатуру Android
  без особенностей `type="number"`. Подключён: Width / Height (Параметры генерации), ширина / высота по умолчанию
  (Настройки), рабочая ширина / высота (Face Fix), тариф GPU, X / Y / Ширина / Высота % (Regional Control).
  Seed — текстовое поле с цифровой клавиатурой.
- Клавиатура не перекрывает поле: в `viewport` добавлено `interactive-widget=resizes-content` (страница уменьшается
  под клавиатуру), сфокусированное поле в окне прокручивается в видимую часть.
- Поля CloudCompute уже хранили строки — не менялись.

Оформление Pixel Fantasy не менялось. Движок, генерация, формат настроек и данные не затронуты.

- **Реальный Android и Brave недоступны.** Проверка выполнена в Chromium с мобильной эмуляцией и касаниями; поведение
  настоящей экранной клавиатуры (появление, изменение высоты окна, IME) эмуляция не воспроизводит. Причина ошибки
