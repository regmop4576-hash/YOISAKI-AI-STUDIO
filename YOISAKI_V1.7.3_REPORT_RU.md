# YOISAKI AI STUDIO v1.7.3 — технический отчёт

Основа — архив `YOISAKI_AI_STUDIO_V1.7.2_GOOGLE_DRIVE_AUTO_SYNC.zip`. Сайт 1.7.3, пакет CloudCompute 1.7.3, протокол движка 1.7.0.

**Не изменены (побайтно):** `engine/` (все 25 файлов) и Colab-блокнот. Это проверяют тесты `test_notebook_package_is_byte_identical_to_engine` и `test_engine_files_match_current_package_manifest`. Загрузка моделей, память GPU, очередь, параметры генерации, Text2Img/Img2Img, Multi-LoRA, Regional Control, ControlNet и SDPose не затрагивались.

**Пометки о способе проверки:**
- **[локально]** — запуск в среде разработки (Linux x86_64, без GPU);
- **[моки]** — с заменителями GPU, Cloudflare, Google или ntfy;
- **[реальный GPU]** — на настоящем GPU. **Таких проверок в этой версии нет.**

### 1.2. Подключение одной кнопкой

- **Запоминание подключения** — только по флажку «Запомнить на этом телефоне». Адрес и токен хранятся в `secrets.json` (права 0600) в папке данных Termux. `state.json` по-прежнему без учётных данных. Токен не отдаётся странице, не попадает в `/api/diagnostics` и в журналы.
- **`POST /api/gpu/autoconnect`** — фоновое подключение к сохранённому серверу:
  - фазы `STARTING → CONNECTING → AUTHENTICATING → LOADING → READY / ERROR` с сообщениями на русском;
  - повторяет попытки до 15 минут (пауза от 3 до 20 с), пока GPU-сервер не готов: DNS, Cloudflare 530/1033, туннель, ошибка ответа движка;
  - **сразу останавливается**, если ожидание не поможет: отклонён токен, несовместимый движок, нет CUDA;
  - «Отключиться» отменяет ожидание.
- **Cloudflare HTTP 530** (туннель без коннектора) распознаётся как `TUNNEL_OFFLINE` (`server/upstream.mjs`).
- **Диагностика по компонентам** (`server/connect-flow.mjs`): Сайт / Туннель / Доступ / Движок и зависимости / GPU-CUDA / Модели. Компонент, до которого проверка не дошла, показывается как «—», а не как READY.
- «Вставить ссылку из буфера», `connected_at`, расчёт стоимости сеанса и предупреждение о простое (15 минут и дольше).

### 1.3. CloudCompute (`cloudcompute/`, скрипты)

- **Постоянная ссылка** `YOISAKI_STABLE_LINK=1`: токен хранится в `config/engine/engine.token` (0600). По умолчанию **выключена**, чтобы обновление не меняло молча прежнее правило «новый токен на каждый запуск». Включается мастером. Отзыв: `./check-cloudcompute.sh rotate-token`.
- **Named Tunnel** `YOISAKI_TUNNEL_MODE=named` + `YOISAKI_PUBLIC_HOSTNAME`. Токен туннеля хранится в `config/engine/cloudflared.token` и передаётся cloudflared через переменную окружения `TUNNEL_TOKEN`, не через аргументы командной строки.
- **Автообнаружение адреса Quick Tunnel** `YOISAKI_RENDEZVOUS=ntfy`. Сервер публикует `{url, ts, sig}` в тему ntfy, имя которой выведено из токена. Подпись — HMAC-SHA256 токеном; сам токен не передаётся. Сайт принимает только подписанную свежую (не старше 24 ч) запись, адрес которой проходит политику хостов провайдера. Реализации в Python и Node побайтно совместимы (проверено тестом).
- **Устойчивость туннеля:** сбой туннеля при старте или во время работы **больше не останавливает движок** (в 1.7.2 после трёх потерь движок гас, а оплата шла). Повторы: сначала сразу, затем через 15, 30, 60, 120 и 300 с. Фаза в `launcher.json` — `TUNNEL_RETRY`.
- Пауза `YOISAKI_TUNNEL_DNS_DELAY` (по умолчанию 5 с) перед первой DNS-проверкой нового имени Quick Tunnel. Это смягчение **неподтверждённой** гипотезы о кэшировании ответа «имя не найдено».
- `setup-cloudcompute.sh` — мастер первой настройки; `autostart-cloudcompute.sh` — автозапуск через systemd или cron @reboot (честно сообщает, если ни того ни другого нет).
- `install-native.sh`: на экране виден ход установки, кэш pip отключён (`PIP_NO_CACHE_DIR=1`), статус ошибки установки проверяется корректно.
- `serve_cloud.py` при ручном запуске объясняет, как запускать правильно, вместо `KeyError: 'YOISAKI_MODEL_ROOT'`.
- `start-cloudcompute.sh` называет неисправный компонент: «движок работает, туннель переподключается» вместо «Движок не запустился».

### 1.4. Google Drive

- **Вход в браузере:** OAuth 2.0 Authorization Code + PKCE (S256), перенаправление на `http://127.0.0.1:<порт>/`. Используется собственный OAuth-клиент пользователя типа Desktop app; scope — только `drive.readonly`.
  - `state` одноразовый, живёт 10 минут; посторонний `state` отклоняется прежним правилом cross-site.
  - Refresh token идёт от Google на локальный сервер и сразу на GPU через существующий `/sync/drive/connect`. На телефоне он не сохраняется (проверено тестом по всем файлам папки данных).
  - Client ID и Secret хранятся в `secrets.json`.
- **Нужна внешняя настройка** — проект Google Cloud и OAuth-клиент (раздел 5 инструкции). Полностью автоматической авторизации без неё нет: Google не разрешает встроить общий клиент для такого доступа.
- **Выбор файлов:** `/sync/start` принимает необязательный `{"paths":[…]}`. Пути лишь выбирают среди файлов, которые сервер сам получил из Drive; прочие поля по-прежнему игнорируются (контракт 1.7.2 сохранён). Сайт предлагает выбор, только если сервер сообщает `selective:true` — серверы 1.7.2 синхронизировали бы всё.
- Способ через Termux (`rclone authorize`) сохранён как «Вариант 2».

### 1.5. CloudCompute API — чего нет и почему

На главной странице cloudcompute.ru заявлен «полный REST API», в меню есть «Справочник API». Однако содержимое справочника не удалось получить: сайт недоступен из среды разработки (прокси 403 / DNS), а в поисковой выдаче страниц справочника нет. Поэтому **адаптер запуска и остановки инстанса не реализован**: эндпоинты пришлось бы выдумать. Вместо него сделаны:
- точная таблица «отключиться / остановить движок / остановить инстанс / удалить инстанс» и её влияние на оплату;
- расчёт стоимости и предупреждение о простое.

Когда будет документация API, адаптер добавляется в локальный сервер. Ключ API должен храниться в `secrets.json` на телефоне, не на GPU.

## 3. Ограничения и риски

1. **Ничего не проверялось на реальном GPU, Cloudflare, Google или Android.** Время запуска «до 10 минут» — цель, а не измерение.
2. **CloudCompute:** запуск и остановка инстанса с сайта не реализованы (раздел 1.5). Автозапуск движка работает только при systemd или cron на инстансе; в арендованных контейнерах их часто нет.
3. **Quick Tunnel без Named Tunnel и без автообнаружения** по-прежнему меняет адрес при каждом запуске — ссылку придётся вставлять снова.
4. **Автообнаружение** зависит от стороннего бесплатного сервиса ntfy.sh (доступность из России не проверялась). Сервис видит адрес туннеля, но не токен.
5. **Named Tunnel** требует домена в Cloudflare. Работа Cloudflare из России и поведение `cloudflared tunnel run` с `TUNNEL_TOKEN` не проверялись на реальной учётной записи.
6. **Google OAuth.** Срок действия 7 дней в режиме Testing и работа непроверенного приложения в режиме Production для личного использования описаны по документации Google и не проверялись. Перенаправление на 127.0.0.1 в Chrome на Android работает, только пока запущен Termux.
7. **Постоянный токен** живёт до ротации: утечка ссылки опаснее, чем в 1.7.2. Компенсация — опция выключена по умолчанию, есть `rotate-token`, токен хранится только в файлах 0600.
8. Пауза перед DNS-проверкой Quick Tunnel лечит **гипотезу**, а не доказанную причину.
9. `/inventory` доступен, только если включена синхронизация Drive (`YOISAKI_DRIVE_SYNC=1`, по умолчанию). Иначе сайт использует `/models` без автообновления.
10. **Colab:** каждый сеанс — новые адрес и токен; полностью автоматического подключения нет. Обходов ограничений Colab в проекте нет.
