# YOISAKI AI STUDIO v1.7.1 — обновление на Android / Termux

Дата: 26 октября 2026. Студия: **1.7.1 CLOUDCOMPUTE EDITION**. Движок и API: **1.7.0**. Это разные версии; несовпадение 1.7.1/1.7.0 здесь правильно.

## Перед обновлением

Дождитесь завершения генераций. Отключение студии не отменяет работу удалённого GPU. Если нужно остановить задание, отмените его до обновления.

Скачайте `YOISAKI_AI_STUDIO_V1.7.1_CLOUDCOMPUTE_UI_FIXED.zip` в Downloads. Не распаковывайте новый код поверх работающей папки. Все команды ниже выполняются на телефоне в Termux; компьютер не нужен.

Проверьте папку старой установки. В примере она называется `~/YOISAKI_AI_STUDIO_V1.4.0_LOCAL_EDITION`. Если вы переименовали её, измените только значение `APP_DIR`. Историческое имя папки 1.4.0 сохранено для совместимости; оно не обозначает установленную версию.

```bash
termux-setup-storage
pkg install -y nodejs-lts unzip
APP_DIR="$HOME/YOISAKI_AI_STUDIO_V1.4.0_LOCAL_EDITION"
ARCHIVE="$HOME/storage/downloads/YOISAKI_AI_STUDIO_V1.7.1_CLOUDCOMPUTE_UI_FIXED.zip"
cd "$APP_DIR"
bash stop.sh
```

Node.js должен быть версии 22–26. Проверка: `node --version`. Приложение должно находиться в домашнем каталоге Termux, а не `/sdcard` или `/storage`.

## Резервная копия

По умолчанию все настройки, пресеты, модели каталога, история и изображения находятся в `~/.local/share/yoisaki-ai-studio`. Если вы задавали `YOISAKI_DATA_DIR`, используйте то же значение при остановке, обновлении и запуске. Скрипт не угадывает пользовательские переменные окружения.

```bash
DATA_DIR="${YOISAKI_DATA_DIR:-$HOME/.local/share/yoisaki-ai-studio}"
BACKUP_DIR="$HOME/yoisaki-backup-$(date +%Y%m%d-%H%M%S)"
mkdir -m 700 "$BACKUP_DIR"
cp -a "$APP_DIR" "$BACKUP_DIR/app"
if [ -d "$DATA_DIR" ]; then cp -a "$DATA_DIR" "$BACKUP_DIR/data"; fi
printf 'Резервная копия: %s\n' "$BACKUP_DIR"
```

Копирование должно завершиться без ошибок. Нужен свободный диск под архив, новую папку и резервные копии, включая все изображения. Бэкап содержит личные данные: не публикуйте его. Ни одну старую папку здесь удалять не требуется.

## Обновление существующей установки

Используйте **новый update.sh из нового архива**. Старый updater не содержит новых проверок и резервного копирования данных.

```bash
PREP_DIR=$(mktemp -d "$HOME/yoisaki-ui-fix.XXXXXX")
unzip -q "$ARCHIVE" -d "$PREP_DIR"
NEW_DIR="$PREP_DIR/YOISAKI_AI_STUDIO_V1.4.0_LOCAL_EDITION"
bash "$NEW_DIR/update.sh" "$ARCHIVE" "$APP_DIR"
```

Если скрипт завершился с ошибкой, прочитайте сообщение и не продолжайте следующую команду вслепую. Он проверяет архив и сборку до остановки сервера, создаёт отдельные копии кода и данных, заменяет папку приложения и запускает сервер. Если запуск новой версии не удался, предыдущий код возвращается; неудачная папка остаётся с суффиксом `.failed-…`. Данные не удаляются. При отказе бэкапа старая установка остаётся на месте, но сервер может быть остановлен.

Нестандартный `YOISAKI_DATA_DIR` внутри папки приложения намеренно отклоняется: сначала скопируйте данные вне папки кода и задайте новое значение переменной. Это предотвращает потерю доступа к данным при смене каталога.

Новый ZIP содержит проверенную production-сборку `dist` и исходники. `node_modules` и Python-окружение не включены. Локальный сервер не требует внешних npm runtime-модулей. `install.sh` проверяет SHA-256 исходников и сборки; если сборка отсутствует или устарела, выполняет `npm ci` и `npm run build` (нужен интернет).

## Первая установка

Только если приложения ещё нет: распакуйте ZIP в новую папку домашнего каталога Termux и выполните:

```bash
cd "$HOME/YOISAKI_AI_STUDIO_V1.4.0_LOCAL_EDITION"
bash install.sh
bash start.sh
```

Не используйте этот раздел для распаковки поверх существующей установки.

## Пересборка и перезапуск вручную

Этот архив использует **React + esbuild + Node.js**, как и входной проект. Next.js runtime и команда `next build` в нём отсутствуют.

```bash
cd "$APP_DIR"
bash stop.sh
npm ci --no-audit --no-fund
npm run typecheck
npm run build
node scripts/build-identity.mjs
bash start.sh
```

Каждая команда должна завершиться успешно. Запускается `127.0.0.1:3000`. Если порт занят, не завершайте все процессы Node подряд: выполните `bash stop.sh` в папке установленного приложения. Новый `start.sh` сообщает о уже работающем сервере и его каталоге; он не выдаёт старый процесс за новую сборку.

## Проверка версии

1. Откройте **http://127.0.0.1:3000/engine**.
2. Видны обе кнопки: **Google Colab** и **CloudCompute**.
3. В настройках: **AMBER CORE · v1.7.1 CLOUDCOMPUTE EDITION**.
4. В статусе: **Версия студии: 1.7.1**. До подключения GPU/VRAM/движок/API показывают «Нет данных».
5. Выполните `bash diagnostics.sh`: версия установленного и запущенного сервера, каталог процесса и результат проверки сборки выводятся отдельно. `node scripts/build-identity.mjs` должен завершиться успешно.

Для проверки HTTP API из Termux:

```bash
curl -s -c "$TMPDIR/yoisaki-version-cookie" -H 'X-Yoisaki-Local: 1' http://127.0.0.1:3000/api/session
curl -s -b "$TMPDIR/yoisaki-version-cookie" -H 'X-Yoisaki-Local: 1' http://127.0.0.1:3000/api/version
```

`studio_version` должен быть `1.7.1`, `edition` — `CLOUDCOMPUTE EDITION`. До подключения `engine_version` и `api_version` равны `null`. На старом совместимом движке поле API может отсутствовать: UI честно покажет «Нет данных».

## Подключение GPU

- **Google Colab:** выберите кнопку, запустите блокнот `colab/YOISAKI_ENGINE_V1.7.0_IMG2IMG_EDITION.ipynb`, вставьте защищённую ссылку в «URL туннеля Colab».
- **CloudCompute:** запустите существующий YOISAKI ENGINE на облачном сервере по `docs/CLOUDCOMPUTE_INSTALL_ANDROID_RU.md`, выберите CloudCompute и вставьте ссылку в «URL сервера CloudCompute».
- `#token=…` автоматически переносится в скрытое поле. Можно ввести адрес и токен отдельно. Нажмите «Подключиться». Сервер проверит `/health` и `/models` с Bearer-токеном.
- Поддерживаются HTTPS адреса на стандартном порту 443. Для Colab — `*.trycloudflare.com`; для CloudCompute — также другой явно введённый публичный DNS-адрес HTTPS. Пути, query-параметры, HTTP и частные IP отклоняются. Произвольный HTTP порт FastAPI нельзя вставлять напрямую: используйте существующий HTTPS-туннель.
- Адрес сохраняется при попытке подключения или смене провайдера. Просто набранный адрес без этих действий — черновик. Адреса двух провайдеров сохраняются отдельно.
- Токены не сохраняются на диск, в браузерное хранилище или экспорт настроек. После переключения провайдера, отключения или перезапуска сервера нужен его токен заново. Перезагрузка страницы не отключает уже установленную серверную сессию.
- Смена провайдера прекращает локальную сессию и опрос старых задач. Уже выполняющаяся удалённая задача может продолжиться. Для её получения явно вернитесь к тому же провайдеру, адресу и токену. Автоматического подключения нет.

## Если ещё видно 1.7.0

Сначала проверьте `bash diagnostics.sh`, путь запущенного процесса и `node scripts/build-identity.mjs`. В исходной поставке строки действительно были 1.7.0; кэш не был основной найденной причиной.

Остановите сервер, запустите из обновлённой папки, закройте старую вкладку Chrome и снова откройте точный адрес `http://127.0.0.1:3000/engine`. Сбросьте только кэш браузера при необходимости. Не очищайте данные Termux и не удаляйте `~/.local/share/yoisaki-ai-studio`. Service Worker в проекте отсутствует; статические ответы имеют `Cache-Control: no-cache`, API — `no-store`.

## Безопасный откат

Запишите путь `.backup-…`, который напечатал updater. Остановите новый сервер. Переместите новый код в отдельную папку, верните старый код на прежнее место:

```bash
cd "$APP_DIR"
bash stop.sh
OLD_CODE="/полный/путь/к/папке.backup-ДАТА"
FAILED_CODE="${APP_DIR}.saved-new-$(date +%Y%m%d-%H%M%S)"
mv "$APP_DIR" "$FAILED_CODE"
cp -a "$OLD_CODE" "$APP_DIR"
cd "$APP_DIR"
bash start.sh
```

`OLD_CODE` необходимо заменить на реальный путь. Обычно откат кода не требует отката данных: схема state.json осталась прежней. Если всё же нужна прежняя копия данных, сначала остановите сервер и сохраните текущий каталог данных под новым именем; только затем скопируйте нужный бэкап на прежнее место. Не затирайте свежие изображения. Настройки провайдера — дополнительное поле preferences, старый код его не использует.

## Что проверено

Установщик, production-сборка, запуск на порту 3000, резервные копии и обновление проверяются в Linux-среде. Настоящий Android/Termux и реальная GPU-сессия CloudCompute/Colab в этой работе недоступны. Подробные результаты — `YOISAKI_V1.7.1_TEST_RESULTS.md`.
