# CloudCompute API — настройка (v1.7.3)

## Что известно и что нет

**Подтверждено** (страница «Доступ к API» в панели CloudCompute): базовый адрес `https://app.cloudcompute.ru/api/v1`, заголовок `Authorization: Bearer cc-…`, разделы Inference / GPU instances / SSH keys, документация `https://cloudcompute.ru/docs/api`.

**Не подтверждено.** Во время разработки 1.7.3 документация была недоступна из среды разработки (сетевая политика: ответ прокси 403 для `cloudcompute.ru` и `app.cloudcompute.ru`; поисковые системы не индексируют страницы справочника). Поэтому **ни один адрес метода не зашит в код**: угадывать пути для платных операций (запуск инстанса) недопустимо.

## Как устроено

- Ключ вводится один раз на странице **GPU → CloudCompute → CloudCompute API** и хранится только в `secrets.json` локального сервера (0600). Странице, GPU-движку, журналам и диагностике он не передаётся (проверено тестами). «Удалить ключ» стирает его из файла.
- Запросы идут только на постоянный хост `app.cloudcompute.ru` (адрес не берётся из запроса → нет SSRF), с проверкой TLS-сертификата, без следования перенаправлениям и с запретом частных IP-адресов в ответе DNS.
- Методы API описываются небольшим **файлом описания** `cloudcompute-api.json` в папке данных (по умолчанию `~/.local/share/yoisaki-ai-studio/`). Файл проверяется строго: только `GET` и `POST`, относительные пути, `{id}` только там, где нужен, обязательное поле `verified_against`. Метода удаления инстанса в описании быть не может.
- Без проверенного описания: ключ сохраняется (проверяется только формат), а панель прямо пишет, что управление инстансами недоступно и почему. Кнопка **ПОДКЛЮЧИТЬ GPU** в этом случае работает как прежнее «подключение одной кнопкой» (инстанс запускается в панели CloudCompute).
- С проверенным описанием: список инстансов (статус, GPU, диск, цена), выбор инстанса, запуск/остановка **с подтверждением**, и сценарий ПОДКЛЮЧИТЬ GPU: проверка инстанса → (если остановлен и вы подтвердили) запуск → ожидание статуса «работает» (до 10 минут) → подключение к движку → модели → READY.

**Ключ API не даёт доступа к движку YOISAKI.** Для движка остаётся отдельная защищённая ссылка с токеном (`./check-cloudcompute.sh link`), которую нужно один раз вставить с «Запомнить». Аутентификация движка не ослаблена.

**«Отключиться» и «остановить движок» не останавливают оплату GPU.** Оплату прекращает только остановка (или удаление) инстанса — в панели CloudCompute или кнопкой «Остановить инстанс», когда метод описан.

## Включение управления инстансами (один раз; сопровождающий или сам пользователь)

1. Откройте https://cloudcompute.ru/docs/api, раздел GPU instances.
2. Скопируйте `config/cloudcompute-api.example.json` в папку данных как `cloudcompute-api.json`.
3. Заполните **по документации**:
   - `operations.list` — метод и путь списка инстансов (относительно `/api/v1`), `items` — поле ответа с массивом (пустая строка, если ответ — сам массив);
   - `operations.get` — путь одного инстанса с `{id}`, `item` — поле с объектом;
   - `operations.start` / `operations.stop` — только если документация их описывает; иначе удалите эти строки (кнопки покажут «в панели CloudCompute»);
   - `fields` — имена полей инстанса (вложенные — через точку: `gpu.name`);
   - `status_map` — значения статуса из документации → `RUNNING`, `STARTING`, `STOPPING`, `STOPPED`, `ERROR`;
   - `verified_against` — ссылка на раздел документации и дата проверки.
4. Перезапустите приложение (`./stop.sh && ./start.sh`). Ошибка в файле видна в панели CloudCompute API, а управление остаётся выключенным.
5. На странице GPU: «Проверить ключ» → «Обновить» → выберите инстанс.

Пересборка сайта не нужна: файл лежит в папке данных, а не в коде. Для публичного дистрибутива сопровождающий может проверить описание один раз и опубликовать его в документации; в репозиторий оно не встраивается автоматически, пока не сверено.

## Прямое HTTPS-подключение без Cloudflare

Документированного способа CloudCompute публиковать порт приложения по HTTPS найти не удалось (документация недоступна). Поэтому прямое подключение **не добавлялось** как отдельная функция. Провайдер CloudCompute в приложении уже принимает любой публичный HTTPS-адрес (порт 443) с проверкой сертификата, Bearer-токеном движка и защитой от частных адресов — если у вас есть свой HTTPS-адрес (Named Tunnel, обратный прокси), его можно использовать. Без него остаётся прежний туннель Cloudflare. Colab не затронут.

## Быстрая установка на инстансе

- **Повторный запуск** переиспользует установленное окружение: `install-native.sh` сверяет хэш закреплённых зависимостей и версии Python и не переустанавливает PyTorch, если ничего не изменилось. Модели лежат на постоянном диске и не скачиваются повторно (синхронизация сверяет размер и контрольную сумму).
- **Готовый Docker-образ (необязательно, новое):** задайте в `config/yoisaki.env` строку `YOISAKI_PREBUILT_IMAGE=ghcr.io/<владелец>/yoisaki-engine:1.7.3-cloudcompute`. `start-cloudcompute.sh` скачает образ и использует его, **только если** метка `org.yoisaki.source` совпадает с хэшем файлов движка в пакете; иначе соберёт образ локально, как раньше. Образ публикует workflow `.github/workflows/engine-image.yml` (запуск вручную или по тегу `v*`). **Не проверено:** ни сборка образа, ни работа Docker на инстансах CloudCompute (в среде разработки Docker недоступен; поддерживает ли CloudCompute Docker внутри инстанса — неизвестно). Без Docker используется нативная установка.
- **Первая установка** выполняется один раз по SSH/терминалу Jupyter: `./setup-cloudcompute.sh` (мастер) и при желании `./autostart-cloudcompute.sh` (автозапуск через systemd или cron, если они есть на инстансе). Выполнять команды на инстансе через API нельзя (возможность не подтверждена), поэтому автоматической установки «из сайта» нет — это ограничение, а не скрытая функция.
- Время запуска пишется в `$YOISAKI_DATA_ROOT/diagnostics/startup-timings.jsonl` и показывается `./check-cloudcompute.sh`. Цель «до 10 минут для уже настроенного окружения» **не измерялась** на реальном GPU и не является гарантией.
