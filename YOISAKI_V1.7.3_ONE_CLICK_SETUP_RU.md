# YOISAKI AI STUDIO v1.7.3 · ONE-CLICK CONNECT EDITION — установка и подключение

Версия сайта **1.7.3**, пакет CloudCompute **1.7.3**, протокол движка **1.7.0** (не изменён: Colab-блокнот v1.7.0 работает как раньше).

Коротко, что меняется в повседневной работе:

| Было (1.7.2) | Стало (1.7.3) |
|---|---|
| После каждого запуска GPU — SSH, поиск ссылки, копирование URL и 64-символьного токена | **CloudCompute:** один раз вставить ссылку и отметить «Запомнить». Дальше: запустить инстанс в панели → сайт → **«Подключить одной кнопкой»** |
| Ошибка «Не удалось подключиться» без объяснений | Ход подключения по шагам и диагностика по компонентам: Туннель / Доступ / Движок / GPU / Модели |
| Новые LoRA могли молча не появиться в генераторе | Все модели видны; несовместимые — с причиной; кнопка «Обновить модели»; список обновляется сам |
| Google Drive: `pkg install rclone`, `rclone authorize`, копирование JSON | **«Войти в Google»** в браузере (после однократной настройки своего OAuth-клиента) |

> **Важно об оплате.** Сайт **не запускает и не останавливает** инстанс CloudCompute: официальный API CloudCompute не удалось проверить по документации, поэтому кнопки управления инстансом не делались на догадках. Запуск, остановка и удаление — в панели CloudCompute. Отключение на сайте и остановка движка **не прекращают** оплату GPU.

## 1. Установка или обновление на Android (Termux)

Требуется Termux из F-Droid и Node.js 22–26 (`pkg install nodejs-lts`).

**Первая установка**

```bash
cd ~
unzip YOISAKI_AI_STUDIO_V1.7.3_ONE_CLICK_CONNECT.zip
cd YOISAKI_AI_STUDIO_V1.4.0_LOCAL_EDITION     # имя папки внутри архива не изменилось
bash install.sh
bash start.sh
```

Откройте в браузере телефона `http://127.0.0.1:3000`.

**Обновление с 1.7.2** (данные, галерея, история и пресеты сохраняются; создаются резервные копии кода и данных):

```bash
bash ~/YOISAKI_AI_STUDIO_V1.4.0_LOCAL_EDITION/update.sh ~/storage/downloads/YOISAKI_AI_STUDIO_V1.7.3_ONE_CLICK_CONNECT.zip ~/YOISAKI_AI_STUDIO_V1.4.0_LOCAL_EDITION
```

**Чтобы не набирать команды каждый день** (по желанию): установите Termux:Widget и создайте `~/.shortcuts/YOISAKI.sh` с одной строкой `bash ~/YOISAKI_AI_STUDIO_V1.4.0_LOCAL_EDITION/start.sh` — запуск сайта будет кнопкой на рабочем столе.

**Откат на 1.7.2:** `update.sh` сохраняет прежний код в папке `…_LOCAL_EDITION.backup-ДАТА`. Либо выполните `update.sh` с исходным архивом `YOISAKI_AI_STUDIO_V1.7.2_GOOGLE_DRIVE_AUTO_SYNC.zip`. Данные 1.7.3 совместимы с 1.7.2: новые сведения лежат в отдельном `secrets.json`, который 1.7.2 просто не читает.

## 2. CloudCompute: первая настройка (один раз, ~15–30 минут)

### 2.1. Установите пакет на сервер (как в 1.7.2)

Скопируйте архив на сервер, распакуйте в `/workspace` и выполните `./start-cloudcompute.sh` — подробности в `YOISAKI_V1.7.2_CLOUDCOMPUTE_SETUP.md` (без изменений). Обновление 1.7.2 → 1.7.3 на сервере: распакуйте новый архив поверх старой папки пакета; модели, venv и настройки в `/workspace/yoisaki-data` не затрагиваются.

### 2.2. Мастер настройки подключения

```bash
cd /workspace/YOISAKI_AI_STUDIO_V1.4.0_LOCAL_EDITION
./setup-cloudcompute.sh
```

Мастер задаёт три вопроса:

1. **Постоянная ссылка** (рекомендуется «Да»). Токен доступа перестаёт меняться при каждом запуске, поэтому сайт может запомнить подключение. Отозвать доступ: `./check-cloudcompute.sh rotate-token` (новый токен начнёт действовать после перезапуска движка).
2. **Адрес сервера:**
   - **1 — Quick Tunnel.** Бесплатно, но адрес меняется при каждом запуске: после перезапуска инстанса ссылку придётся вставить снова.
   - **2 — Quick Tunnel + автообнаружение (бесплатно, без домена).** Сервер публикует новый адрес в сервисе `ntfy.sh`, подписанный вашим токеном; сам токен туда не передаётся, а поддельный адрес сайт отбрасывает. Это сторонний бесплатный сервис без гарантий доступности.
   - **3 — Cloudflare Named Tunnel.** Постоянный адрес на вашем домене (нужен домен, подключённый к бесплатному аккаунту Cloudflare). В Cloudflare: *Zero Trust → Networks → Tunnels → Create tunnel (Cloudflared)*, затем *Public Hostname*: ваш адрес, Service `HTTP`, URL `127.0.0.1:8765`. Мастер спросит адрес и токен туннеля (ввод скрыт); токен хранится в `config/engine/cloudflared.token` с правами 0600.
3. **Автозапуск движка при старте инстанса.** Работает, если на сервере есть systemd или cron. Во многих арендованных контейнерах их нет — тогда мастер прямо об этом скажет. В этом случае после запуска инстанса нужно один раз выполнить `./start-cloudcompute.sh`; сайт подождёт его и подключится сам.

Примените настройки:

```bash
./stop-cloudcompute.sh && ./start-cloudcompute.sh
./check-cloudcompute.sh link
```

### 2.3. Запомните подключение на телефоне

Сайт → **GPU** → **CloudCompute** → **«Вставить ссылку из буфера»** (или вставьте вручную) → оставьте отмеченным **«Запомнить на этом телефоне»** → **«Подключиться»**.

Токен сохраняется только в приложении на телефоне (`~/.local/share/yoisaki-ai-studio/secrets.json`, права 0600). Он не хранится в браузере и не показывается на страницах.

## 3. CloudCompute: каждый следующий запуск

1. Запустите инстанс в панели CloudCompute.
2. Откройте YOISAKI AI STUDIO → **GPU** → **CloudCompute**.
3. Нажмите **«Подключить одной кнопкой»**.
4. Сайт покажет шаги: *Ожидание запуска GPU → Подключение → Проверка доступа → Загрузка движка и моделей → Готово к генерации*. Он ждёт загрузки сервера до 15 минут. Ожидание можно отменить.
5. Генерируйте.

Если автозапуска на сервере нет, между шагами 1 и 3 один раз выполните `./start-cloudcompute.sh`: через SSH или командой запуска в настройках инстанса, если панель её поддерживает.

**Когда закончили:** остановите или удалите инстанс в панели CloudCompute (см. раздел 6).

## 4. Google Colab

Порядок работы Colab не изменился: блокнот `colab/YOISAKI_ENGINE_V1.7.0_IMG2IMG_EDITION.ipynb` → «Подготовить панель» → «Запустить». В Colab каждый сеанс получает новый адрес и новый токен, а бесплатные сеансы Colab нельзя запускать без вашего участия. Поэтому полностью автоматического подключения для Colab нет и обходов ограничений Colab в проекте нет.

Что стало проще: скопируйте ссылку из панели Colab, затем на сайте нажмите **GPU → Google Colab → «Вставить ссылку из буфера» → «Подключиться»**. Флажок «Запомнить» для Colab действует до конца сеанса Colab: например, после перезапуска Termux можно переподключиться одной кнопкой.

## 5. Google Drive через браузер (CloudCompute)

### 5.1. Один раз: свой OAuth-клиент Google (~10 минут)

Google не разрешает встроить в приложение общий OAuth-клиент для такого доступа, поэтому нужен собственный (бесплатно). Шаги в браузере телефона:

1. `console.cloud.google.com` → создайте проект → *APIs & Services → Library* → включите **Google Drive API**.
2. *OAuth consent screen*: тип **External**, добавьте свой Gmail в *Test users*. Если приложение остаётся в режиме *Testing*, Google ограничивает срок действия доступа 7 днями. Чтобы этого не было, переведите приложение в *In production*: Google покажет предупреждение о непроверенном приложении, но это ваше собственное приложение. *(Эти правила Google описаны по документации Google и не проверялись в этой разработке на реальном аккаунте.)*
3. *Credentials → Create credentials → OAuth client ID* → тип **Desktop app** («Приложение для ПК»).
4. На сайте: **Модели → GOOGLE DRIVE AUTO SYNC → «Подключить Google Drive»**. Вставьте Client ID и Client Secret и нажмите **«Сохранить OAuth-клиент на телефоне»**.

### 5.2. Подключение

**«Войти в Google и разрешить доступ»** → выберите аккаунт с папкой `YOISAKI_AI_STUDIO/models` → разрешите доступ (только чтение). Вы автоматически вернётесь на страницу «Модели».

- Доступ только на чтение (`drive.readonly`).
- Refresh token уходит сразу на ваш GPU-сервер (`rclone.conf`, 0600) и на телефоне не сохраняется.
- Если инстанс удалён вместе с диском, нажмите «Войти в Google» ещё раз.

### 5.3. Выбор моделей и синхронизация

**«Проверить модели»** → отметьте нужные файлы → **«Синхронизировать выбранные»**. Кнопка «Синхронизировать» по-прежнему загружает все недостающие модели. Проверка целостности (размер, контрольная сумма Google Drive, заголовок safetensors) осталась прежней. После загрузки список моделей на сайте обновляется сам.

Старый способ через Termux (`rclone authorize`) остался как «Вариант 2».

## 6. Оплата: что останавливает деньги

| Действие | Что происходит | Оплата GPU | Модели |
|---|---|---|---|
| «Отключиться» на сайте | Сайт отключён, движок и инстанс работают | **идёт** | на месте |
| `./stop-cloudcompute.sh` | Движок остановлен, видеопамять свободна | **идёт** | на месте |
| Остановить инстанс в панели | GPU выключен | прекращается, но **хранение диска оплачивается** (у вас в панели указывалось 24,94 ₽/ч — проверьте фактические списания) | на месте, если диск постоянный |
| Удалить инстанс в панели | Всё удалено | прекращается полностью | **удаляются с диска**; копия остаётся в Google Drive |

На странице GPU (CloudCompute) можно указать тариф ₽/час. Сайт покажет время подключения, приблизительную стоимость и предупредит, если GPU простаивает 15 минут и дольше. Расчёт приблизительный: оплата идёт с момента запуска инстанса, а не с момента подключения.

## 7. Диагностика без SSH

**GPU → Диагностика** показывает состояние компонентов:

| Компонент | ОШИБКА / ОЖИДАНИЕ означает |
|---|---|
| Туннель / адрес | Инстанс выключен, движок ещё запускается, адрес сменился или проблемы DNS |
| Доступ (токен) | Токен сменили (ротация) или по адресу другой сервер. Вставьте новую ссылку один раз |
| Движок и зависимости | Туннель есть, но движок не отвечает или его версия несовместима |
| GPU / CUDA | Движок работает, но видеокарта недоступна |
| Модели | Список не обновился (показан прежний) или нет совместимого checkpoint |

«Технический журнал для разработчиков» внизу страницы содержит коды последних событий. Токенов в нём нет.

**На сервере** (по желанию):

- `./check-cloudcompute.sh models` — каждая модель, её совместимость и причина. Например: «Vesper_Nova.safetensors: НЕСОВМЕСТИМА · ошибка чтения: Повреждён заголовок» — значит, файл не докопирован и его нужно скопировать заново.
- `./check-cloudcompute.sh` — GPU, CUDA, диск, версии, состояние движка.
- `./check-cloudcompute.sh logs` — журналы (токены скрыты).

## 8. Если новая LoRA не видна

1. **Генерация → «Обновить модели»** (рядом со списком LoRA). На CloudCompute 1.7.3 список обновляется и сам, примерно в течение 30 секунд после появления файла.
2. Если LoRA видна с пометкой **«несовместима»**, откройте «Несовместимые модели» под списком — там указана причина:
   - *«Файл не читается как safetensors»* — файл повреждён или не докопирован. Сверьте размер и SHA-256 с исходником и скопируйте заново, затем «Обновить модели». Перезапуск GPU не нужен.
   - *«Метаданные LoRA указывают другую базовую модель (…)»* — в самом файле записана база SD 1.x/2.x, Flux или SD3. Если LoRA обучена на SDXL, метаданные файла неверны; такие LoRA движок не загружает.
3. Если появилось сообщение «Список моделей не обновился: …», значит, показан прежний список, а причина указана в сообщении.
