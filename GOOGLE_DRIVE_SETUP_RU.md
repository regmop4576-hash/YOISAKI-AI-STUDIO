# Google Drive Easy Connect — настройка (v1.7.3)

## Что изменилось

| Было (1.7.2) | Стало (1.7.3 Easy Connect) |
|---|---|
| `rclone authorize` в Termux и копирование JSON-токена | Кнопка «Войти через Google» в браузере телефона |
| Нужен подключённый GPU | Аккаунт и папка настраиваются **без GPU** |
| Папка задаётся переменной `YOISAKI_DRIVE_PATH` на сервере | Папка выбирается в обозревателе папок на странице «Модели» |
| Нет предпросмотра | «Проверить модели в Drive»: сколько checkpoint / LoRA / VAE в папке, без GPU |
| Токен вводится заново для каждого сервера | Доступ передаётся на ваш GPU-сервер CloudCompute автоматически при подключении |

Ручной способ через Termux сохранён в разделе «Дополнительно» на странице «Модели» — на случай, если вход через браузер невозможен.

## Как это выглядит для пользователя

1. **Модели → GOOGLE DRIVE → «Войти через Google».**
2. Google: выбор аккаунта → разрешение «Просмотр файлов на Google Диске».
3. Возврат в приложение, открывается выбор папки: «Мой диск» или «Доступные мне» → папка, в которой лежат `checkpoints/`, `loras/`, `vae/` (обычно `YOISAKI_AI_STUDIO/models`) → «Выбрать».
4. Приложение показывает, сколько моделей найдено. Готово.
5. Когда подключится GPU CloudCompute, доступ передаётся на сервер, и (если включено) начинается загрузка недостающих моделей.

На странице три **независимых** состояния: «Аккаунт Google Drive» (подключён / нет / нужен повторный вход), «GPU-движок» (онлайн / офлайн), «Синхронизация моделей» (доступна / недоступна с причиной / выполняется).

## OAuth-клиент: откуда он берётся

Google не выдаёт доступ к Drive без OAuth-клиента, зарегистрированного в Google Cloud. Есть два варианта, приложение поддерживает оба:

### Вариант A. Общий клиент дистрибутива (подготавливает сопровождающий)

Если сопровождающий публичной сборки зарегистрировал клиент (см. `PUBLIC_GITHUB_SETUP.md`) и положил его в `config/google-oauth-client.json` или переменные `YOISAKI_GOOGLE_CLIENT_ID` / `YOISAKI_GOOGLE_CLIENT_SECRET`, пользователь просто нажимает «Войти через Google». Каждый пользователь входит **в свой** аккаунт; клиент лишь идентифицирует приложение и сам по себе не даёт доступа ни к чьему Drive.

### Вариант B. Собственный клиент пользователя (≈10 минут, один раз)

Нужен, если общего клиента в установке нет (так по умолчанию в репозитории — **в нём нет никаких учётных данных**):

1. https://console.cloud.google.com → создайте проект.
2. APIs & Services → Library → **Google Drive API** → Enable.
3. OAuth consent screen → External → добавьте свой Gmail в **Test users**.
4. Credentials → Create credentials → OAuth client ID → тип **Desktop app** («Приложение для ПК»).
5. На странице «Модели» раскройте «Нужен OAuth-клиент Google», вставьте Client ID и Client Secret → «Сохранить OAuth-клиент на телефоне» → «Войти через Google».

Срок действия: в режиме **Testing** Google отзывает refresh token через **7 дней** — приложение покажет «Нужен повторный вход» (папка сохранится). Чтобы этого не было, переведите приложение в **In production**; без проверки Google будет показывать экран «Приложение не проверено» (для личного клиента это допустимо, лимит — 100 пользователей).

## Выбранная архитектура OAuth и почему

**OAuth 2.0 Authorization Code + PKCE (S256), loopback-перенаправление `http://127.0.0.1:<порт>/`, клиент типа «Desktop app».**

| Вариант | Оценка |
|---|---|
| **Authorization Code + PKCE, loopback, Desktop app** — выбран | Google поддерживает loopback-перенаправление на `127.0.0.1` с любым портом **только** для клиентов типа Desktop app (для Web/Android/iOS — нет; для Android/iOS Google его отключил). Локальный сервер Termux принимает код, обменивает его и хранит refresh token у себя. Внешний сервис не нужен. `state` одноразовый (10 минут), PKCE защищает код. |
| Google Identity Services (GIS) token model | Выдаёт только короткий access token в браузере, без refresh token; для фоновой синхронизации на GPU непригоден, а хранить токены в браузере требование запрещает. |
| Google Picker API + `drive.file` | Требует Web-клиент с зарегистрированным JavaScript-источником и API-ключ, загрузку скрипта `apis.google.com` (сейчас CSP приложения это запрещает) и даёт доступ только к **явно выбранным файлам**. См. ниже. |
| Внешний HTTPS-сервис обратного вызова | Нужен только для Web-клиента. Добавил бы инфраструктуру, которую кто-то должен содержать и которой пришлось бы доверить коды авторизации. Не нужен — не реализован. |

Ограничения выбранного варианта: перенаправление на `127.0.0.1` в Chrome на Android работает, пока запущен Termux (сервер должен принимать запрос). **Реальная авторизация Google в этой версии не проверялась** — только тестовыми двойниками.

## Область доступа: `drive.readonly`, а не `drive.file`

- `drive.file` даёт доступ только к файлам, созданным приложением или **явно выбранным** пользователем (Picker). Доступ к уже существующей папке с вложенными `loras/characters/…` через `drive.file` **не продемонстрирован** и по документации Google не гарантируется: выбор папки в Picker не делает автоматически доступным её содержимое. Синхронизация целой библиотеки моделей на этом не работает.
- Поэтому используется `https://www.googleapis.com/auth/drive.readonly` — **только чтение**. Приложение ничего не создаёт, не изменяет и не удаляет в Drive (на GPU выполняются только `rclone lsjson` и `rclone cat`, это проверено тестами).
- Честно: технически `drive.readonly` позволяет читать **любые** файлы аккаунта; приложение читает только выбранную папку. Это сказано пользователю прямо на странице.

**Последствия для публичного распространения.** `drive.readonly` — *restricted scope* Google. Публичное приложение (общий клиент, режим In production, больше 100 пользователей) должно пройти проверку Google **и ежегодную оценку безопасности (CASA)** у аккредитованного аудитора. Без неё — экран «непроверенное приложение» и лимит 100 пользователей. Безопасные альтернативы: (1) каждый пользователь создаёт свой клиент (вариант B) — проверка не нужна; (2) пользователь сам кладёт модели в папку, созданную приложением, — тогда хватило бы `drive.file`, но это требует загрузки моделей через приложение и в этой версии не реализовано.

## Где хранятся данные

| Что | Где | Кто видит |
|---|---|---|
| Refresh token Google | `secrets.json` локального сервера (права 0600, папка 0700) | Только локальный сервер; **не браузер**, не `state.json`, не журналы |
| Access token | Только в памяти локального сервера (≈1 час) | — |
| Аккаунт (email, имя), выбранная папка | `secrets.json` | Странице показываются email и путь папки |
| Копия токена для загрузки | GPU-сервер CloudCompute: `config/rclone/rclone.conf` (0600) | Только ваш GPU-сервер (по защищённому каналу движка) |

Отключение («Отключить Google Drive») отзывает доступ в Google (`oauth2.googleapis.com/revoke`, токен — в теле запроса, не в URL), удаляет токен с телефона и, если GPU подключён, с сервера. Отзыв в Google делает недействительной и копию на GPU.

## Ошибки и что делать

| Сообщение | Причина / действие |
|---|---|
| «Нужен повторный вход» | Токен истёк (Testing: 7 дней), отозван или сменён пароль → «Войти через Google снова» |
| «Не включён Google Drive API» | В проекте Google Cloud включите Google Drive API |
| «Google Drive отказал в доступе» | На экране Google не отмечено разрешение или папка недоступна аккаунту |
| «Сервер CloudCompute старше 1.7.3…» | Обновите пакет на сервере: старый сервер не принимает выбранную папку и использует `YOISAKI_DRIVE_PATH` |
| «Папка controlnet/ не синхронизируется» | Это норма: ControlNet движка использует свои встроенные модели (OpenPose, Canny, Depth), а не файлы из папки |
